02

FOUNDATION

Review: How desktop virtualization works

In desktop virtualization, a physical computer called the host runs virtualization software. That software creates virtual computers called virtual machines (VMs). Each VM receives virtualized hardware such as processors, memory, storage, display devices, and network adapters. An operating system installed inside the VM is called the guest operating system.

VirtualBox and VMware desktop products are commonly used as hosted hypervisors. They operate on top of a host operating system and allow users to run additional operating systems in isolated virtual environments. This makes them useful for training, software testing, cybersecurity laboratories, legacy applications, operating-system experiments, development, and demonstrations.

Instructor note: A virtual machine behaves like a separate computer, but its virtual hardware ultimately depends on the capacity and configuration of the physical host.
03

PLATFORM 1

Oracle VirtualBox

Oracle VirtualBox is a general-purpose desktop virtualization platform used to create, configure, run, clone, and manage virtual machines. It provides a graphical management interface and command-line management capabilities. For teaching environments, it is particularly useful because students can work with multiple guest operating systems while learning the structure of a VM.

Major VirtualBox components

VirtualBox Manager

The central interface where virtual machines are created, organized, configured, started, paused, and removed.

Virtual Media

Virtual hard disks and ISO images are attached to virtual storage controllers and used like disks or installation media.

Virtual Networking

Network adapters can use NAT, bridged, host-only, internal, and other virtual networking arrangements.

Guest Additions

Optional software installed inside the guest to improve display, pointer integration, shared folders, and other usability features.

04

PLATFORM 2

VMware desktop virtualization

VMware provides several virtualization products. In a desktop classroom context, the focus is typically on products that create and run VMs on a workstation. Their basic operating model is similar to VirtualBox: create a VM, select or attach an installation source, assign resources, install the guest operating system, and then install guest integration software.

VMware also has enterprise virtualization technologies, but those should be distinguished from desktop hosted virtualization. For example, a desktop hypervisor runs as an application on a host operating system, while enterprise bare-metal hypervisors are designed to run directly on server hardware.

COMPARISON

VirtualBox vs VMware: conceptual comparison

Area VirtualBox VMware Desktop Products
Primary role Hosted desktop virtualization and VM management. Hosted desktop virtualization with a mature workstation-oriented workflow.
VM creation Wizard-based creation with configurable hardware and storage. Wizard-based creation with guest and hardware configuration options.
Virtual disks Supports its native virtual disk format and several compatible formats. Commonly uses VMware virtual disk files for workstation VMs.
Guest integration Guest Additions. VMware Tools.
Networking Includes NAT, bridged, host-only, and internal networking concepts. Includes NAT, bridged, and host-only style network configurations.

Important: Do not select a virtualization platform only because it is familiar. Consider the host operating system, hardware capability, required guest operating system, licensing, networking features, lab objectives, and compatibility requirements.

PREPARATION

Host requirements before creating a VM

A virtual machine competes with the host for processor time, memory, storage capacity, and input/output bandwidth. Before creating VMs, the instructor should teach students to check whether the physical computer can safely provide enough resources.

✓
Hardware virtualization

Confirm that processor virtualization support is available and enabled when required.

✓
Memory capacity

Leave enough RAM for the host operating system while assigning memory to the guest.

✓
Free storage

Provide adequate disk space for the VM, guest OS, applications, snapshots, and temporary files.

✓
Installation media

Prepare a legitimate ISO image or another supported installation source for the guest operating system.

✓
Network plan

Decide whether the VM needs internet access, LAN visibility, host-only communication, or complete isolation.

✓
Recovery plan

Create a clean baseline snapshot before risky experiments or configuration changes.

07

STEP-BY-STEP

Creating a virtual machine

Although the exact buttons differ between products and versions, the underlying workflow is nearly the same. Students should understand the decisions made during VM creation rather than merely memorize a sequence of clicks.

1

Create a new VM

Choose the command to create a new virtual machine. Give the VM a descriptive name such as Ubuntu-Networking-Lab or Windows-Testing-VM.

2

Select the guest operating system

Identify the OS family and architecture. This helps the hypervisor choose reasonable default virtual hardware settings.

3

Assign processor and memory

Allocate enough resources for the guest without starving the host. More is not always better; over-allocation can reduce overall system performance.

4

Create a virtual disk

Choose the disk format, maximum capacity, and allocation behavior. The virtual disk is stored as one or more files on the host.

5

Attach the installation ISO

Connect the operating-system ISO to the VM's virtual optical drive so the VM can boot into the installer.

6

Review network and display settings

Choose an appropriate network mode and verify that the VM has reasonable display memory and graphics settings.

7

Start the VM and install the OS

Power on the VM, follow the normal operating-system installation process, and install updates when appropriate.

8

Install guest integration tools

Install VirtualBox Guest Additions or VMware Tools to improve interaction between the host and guest.

08

CONFIGURATION

CPU and memory allocation

CPU and memory settings directly affect both the guest and host. Allocating too little can make the guest unusable, while assigning too much can slow the host and every other VM. Students should learn to size VMs according to workload rather than choosing maximum values.

Virtual CPUs (vCPUs)

A VM is assigned one or more virtual processors. The hypervisor schedules their work on the physical processor cores available to the host.

  • Start with a modest number of vCPUs for simple labs.
  • Increase only when the guest workload requires it.
  • Do not allocate all host CPU capacity to a single VM.

Virtual memory (RAM)

The VM receives a defined amount of host memory while it is running. The host still needs enough memory for its own operating system and applications.

  • Follow the guest OS minimum and recommended requirements.
  • Keep a safety margin for the host.
  • Close unnecessary host applications during heavy labs.
Rule of thumb for classroom discussion: resource allocation should be sufficient, measurable, and justified. Students should be able to explain why they selected a specific number of vCPUs, memory size, and disk capacity.
09

VIRTUAL STORAGE

Virtual disks, ISO images, and storage behavior

A virtual hard disk is normally represented by a file or set of files on the host. Inside the VM, however, the guest operating system sees the virtual disk as if it were a physical storage device. This abstraction allows the VM to be copied, backed up, cloned, or moved more easily than a physical machine.

Virtual DiskStores the guest operating system, applications, settings, and data.
ISO ImageA disk-image file commonly used as bootable installation media.
Dynamically Allocated DiskConsumes host storage progressively until its configured maximum size is reached.
Fixed-Size DiskReserves the configured storage space in advance, depending on platform behavior.
Storage ControllerPresents virtual storage devices to the guest through emulated or virtualized controller types.
Disk Snapshot ChainRecords changes relative to an earlier state and can grow as the VM continues to be used.
Storage warning: Snapshots are not a substitute for backups. Snapshot chains can consume significant host storage, and a damaged host storage device can still affect the VM and its snapshots.
10

NETWORKING

Understanding virtual network modes

Virtual networking determines how a VM communicates with the host, other VMs, the local network, and the internet. Selecting the correct mode is an important part of designing a safe and functional laboratory.

NAT

The VM typically uses the host's network connection to reach external networks while remaining less directly exposed to the local LAN.

Typical use: General internet access for a training VM.

Bridged

The VM is placed more directly onto the same network as the host and can behave like another networked computer on the LAN.

Typical use: Server testing and LAN communication.

Host-Only

The VM communicates through a virtual network involving the host, usually without ordinary direct external-network access.

Typical use: Controlled host-to-guest laboratory communication.

Internal / Isolated

VMs communicate within a private virtual network while being separated from normal host or external network paths, depending on configuration.

Typical use: Security exercises and isolated multi-VM labs.
11

INTEGRATION

VirtualBox Guest Additions and VMware Tools

A newly installed guest operating system can run without advanced integration, but the experience may be limited. Guest integration packages install drivers and services inside the guest so the VM works more smoothly with the virtualization platform.

Improved display

Allows better resolution handling and more responsive virtual display behavior.

Pointer integration

Improves mouse movement between the host desktop and the VM window.

Shared folders

Enables configured host directories to be exposed to the guest for controlled file exchange.

Guest awareness

Provides services that help the hypervisor interact with and report information about the guest.

Security reminder: Convenience features such as clipboard sharing, drag-and-drop, and shared folders increase interaction between host and guest. Disable them in malware analysis or other untrusted-lab scenarios unless they are specifically required.
12

STATE MANAGEMENT

Snapshots, cloning, and rollback

A snapshot records a recoverable point in a VM's state. It is useful before software installation, registry or configuration changes, networking experiments, or security exercises. A clone creates another VM based on an existing VM and is useful when several students or test scenarios need similar starting environments.

13

DATA EXCHANGE

Shared folders, clipboard, and removable media

Host-to-guest file exchange should be planned rather than enabled automatically. Shared folders are convenient for classroom exercises, while ISO images and virtual removable media can be used when stronger separation is desired. Clipboard and drag-and-drop features may also be available after guest integration tools are installed.

Good classroom use

  • Transfer laboratory instructions into a trusted VM.
  • Export student work to a designated host folder.
  • Mount a read-only ISO containing approved training files.
  • Use clearly named folders for each class or lab activity.

When to restrict sharing

  • Malware analysis or untrusted software testing.
  • Security exercises involving suspicious files.
  • Demonstrations where guest isolation is the learning objective.
  • Any situation where host files must not be exposed to the guest.
14

SECURITY

Safe virtualization practices

01

Use legitimate software and OS images

Obtain hypervisors, extensions, guest tools, and operating-system media from trusted or authorized sources.

02

Keep the host and hypervisor updated

Security of the VM depends partly on the software layer that runs and controls it.

03

Minimize unnecessary integration

Disable shared clipboard, drag-and-drop, shared folders, USB passthrough, or networking when a lab does not require them.

04

Use snapshots before controlled experiments

Create a clean recovery point, name it clearly, and document why it was taken.

05

Do not assume a VM makes risky activity safe

Virtualization provides isolation boundaries, but poor configuration can still expose the host, local network, or data.

TROUBLESHOOTING

Common problems and diagnostic approach

Problem Likely area to investigate Recommended diagnostic action
64-bit guest options are unavailable Hardware virtualization or conflicting host virtualization settings Check firmware virtualization support and host virtualization configuration.
VM is extremely slow Insufficient or excessive resource allocation; host overload Review host CPU/RAM usage and reduce unnecessary VM resources or host applications.
No bootable medium ISO not attached, empty virtual disk, or incorrect boot order Verify installation media and VM boot configuration.
No internet connection Virtual adapter, network mode, guest IP settings, host connectivity Check adapter enablement, NAT/bridged selection, guest network configuration, and host network status.
Cannot access local network server Wrong network mode or firewall rules Confirm whether the lab requires bridged or another LAN-visible configuration.
Screen will not resize properly Missing guest integration drivers Install or repair Guest Additions / VMware Tools and restart the guest if required.
Shared folder is missing Guest integration, permissions, mount settings Verify sharing configuration, guest tools, user permissions, and mount location.
Snapshot consumes large storage Long-running snapshot chain and many disk changes Review snapshot purpose, available host storage, and consolidation strategy.

Professional troubleshooting sequence

Observe→Identify Layer→Check Configuration→Test One Change→Verify Result→Document

GUIDED LABORATORY

Lab Exercise: Build and validate a training VM

LAB ACTIVITY

Create a clean, networked test virtual machine

Use either VirtualBox or a VMware desktop hypervisor. The purpose is to demonstrate understanding of the workflow rather than depend on a specific interface version.

60–90
minutes

Required materials

  • A computer with a supported virtualization platform installed.
  • An approved guest operating-system installation ISO.
  • Sufficient host memory and free storage.
  • A laboratory worksheet or digital document for recording configuration decisions.

Procedure

  1. Create the VM. Use a clear name that identifies the guest OS and laboratory purpose.
  2. Document host resources. Record the host CPU, total RAM, and available storage before assigning VM resources.
  3. Assign guest resources. Configure a reasonable number of virtual CPUs, memory, and virtual-disk capacity.
  4. Attach the ISO. Mount the approved installer to the VM's virtual optical drive.
  5. Configure networking. Start with NAT unless the laboratory specifically requires another topology.
  6. Install the guest OS. Complete normal OS setup and create a designated student or laboratory account.
  7. Install guest integration tools. Install Guest Additions or VMware Tools as appropriate.
  8. Test the display. Resize the VM window and verify that display integration functions correctly.
  9. Test networking. Verify the expected network path according to the selected virtual network mode.
  10. Create a shared folder only if required. Confirm that file exchange works and explain the security trade-off.
  11. Take a baseline snapshot. Name it Clean-Baseline and write a short description.
  12. Perform a controlled change. Install a harmless application or change a visible setting.
  13. Restore the snapshot. Confirm that the VM returns to the earlier baseline state.
  14. Shut down correctly. Use the guest operating system's normal shutdown procedure before closing the hypervisor.

Expected learning evidence

The student should be able to present the VM configuration and explain the purpose of each major setting: guest OS selection, CPU, RAM, disk, ISO, network mode, guest tools, shared folders, and snapshot.

CLASS DISCUSSION

Questions for deeper understanding

  1. Why can assigning too much RAM to a VM make the complete computer slower?
  2. When would NAT be more appropriate than bridged networking?
  3. Why should a cybersecurity lab avoid unnecessary shared folders and clipboard integration?
  4. What is the practical difference between creating a snapshot and creating a clone?
  5. Why is a snapshot not considered a complete backup strategy?
  6. What could happen if the host disk becomes full while several snapshots are active?
  7. Why should students document the reason for each VM resource allocation?
  8. How does desktop hosted virtualization differ conceptually from a bare-metal server hypervisor?

LESSON SUMMARY

Key concepts to remember

1

VirtualBox and VMware desktop products allow multiple isolated guest operating systems to run on a physical host.

2

A VM receives virtual CPU, memory, storage, display, and network hardware from the virtualization layer.

3

Correct resource allocation balances guest performance with host stability.

4

NAT, bridged, host-only, and isolated networking support different communication requirements.

5

Guest Additions and VMware Tools improve integration between the guest and virtualization platform.

6

Snapshots support rollback, while clones create additional VM instances for separate use.

7

Shared folders and clipboard integration are convenient but should be limited in untrusted environments.

8

Professional VM administration requires documentation, security awareness, troubleshooting discipline, and recovery planning.

GLOSSARY

Important terms

Host
The physical computer and operating system that provide resources to the virtualization platform.
Guest
The operating system installed inside a virtual machine.
Hypervisor
The virtualization layer that creates and manages virtual machines and their access to resources.
Virtual Machine
A software-defined computer with virtualized CPU, memory, storage, display, and network devices.
ISO Image
A disk-image file often used as virtual installation media.
vCPU
A virtual processor assigned to a virtual machine.
Virtual Disk
A host file or collection of files presented to the guest as a disk device.
NAT
A networking mode that commonly allows the guest to reach outside networks through the host's connection.
Bridged Networking
A mode that connects the VM more directly to the host's physical network.
Host-Only Networking
A private virtual network used primarily for communication between host and VM.
Snapshot
A recoverable point representing a VM state at a particular time.
Clone
A separate VM created from an existing virtual machine.
Guest Additions
VirtualBox guest-side integration drivers and utilities.
VMware Tools
VMware guest-side integration drivers and services.
