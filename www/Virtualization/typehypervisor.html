Foundation

Introduction to Hypervisors

Modern computing environments frequently require multiple operating systems and applications to share a single physical computer. Instead of assigning one physical server to every application, organizations can use virtualization to divide computing resources into multiple isolated environments.

At the center of this process is software called a hypervisor. The hypervisor controls access to the physical processor, memory, storage, and network resources and distributes those resources to individual virtual machines.

Hypervisors are generally classified into two major architectural categories: Type 1 hypervisors and Type 2 hypervisors.

!

Central Idea

A hypervisor allows several independent virtual computers to operate on one physical computer while maintaining controlled access to physical hardware.

Core Concept

Virtualization Fundamentals

Virtualization is the process of creating a software-based representation of computing resources that would traditionally be provided by dedicated physical hardware.

A physical server may contain a processor, RAM, storage devices, and network interfaces. Virtualization allows those physical resources to be divided into virtual resources that can be assigned to several virtual machines.

Physical Resources vs Virtual Resources

Physical Resources

  • Physical CPU cores
  • Installed RAM
  • Physical disks or SSDs
  • Physical network adapters
  • Motherboard and hardware devices

Virtual Resources

  • Virtual CPUs or vCPUs
  • Virtual memory
  • Virtual disks
  • Virtual network adapters
  • Virtual hardware devices
04

Core Technology

What Is a Hypervisor?

A hypervisor, sometimes called a Virtual Machine Monitor (VMM), is the virtualization layer responsible for creating, executing, isolating, and managing virtual machines.

The hypervisor presents each virtual machine with virtual hardware. To the guest operating system, this virtual hardware appears similar to a physical computer.

01

Resource Allocation

Assigns CPU processing time, memory capacity, storage, and network resources to virtual machines.

02

Isolation

Maintains separation between virtual machines so that workloads can operate independently.

03

Hardware Abstraction

Hides many physical hardware details and presents standardized virtual hardware to guest operating systems.

04

Execution Control

Coordinates how virtual machines access physical processing resources and privileged CPU functions.

05

Virtual Device Management

Provides virtual disks, network adapters, controllers, and other devices required by the guest operating system.

06

Lifecycle Management

Supports operations such as starting, stopping, suspending, cloning, and managing virtual machines.

05

Bare-Metal Architecture

Type 1 Hypervisors

A Type 1 hypervisor operates directly on the physical server hardware rather than being installed as a normal application inside a conventional desktop operating system.

This architecture is commonly called bare-metal virtualization.

The hypervisor becomes the primary virtualization control layer between the physical hardware and the virtual machines. This architecture is commonly selected for servers, data centers, private clouds, enterprise infrastructure, and other environments where performance, scalability, isolation, and centralized management are important.

How Type 1 Works

1

Physical Server Starts

The computer firmware initializes the physical CPU, memory, storage devices, network interfaces, and other hardware.

2

Hypervisor Loads

The virtualization platform initializes and takes responsibility for managing the server's resources.

3

Virtual Machines Are Defined

Administrators assign virtual processors, memory, virtual disks, network interfaces, and other configuration parameters to individual VMs.

4

Guest Operating Systems Start

Each virtual machine boots its own guest operating system using the virtual hardware supplied by the hypervisor.

5

Hypervisor Coordinates Resources

CPU execution, memory access, storage operations, and network traffic are coordinated according to the platform's resource-management policies.

Common Type 1 Platforms

E

VMware ESXi

Bare-metal virtualization platform commonly used in enterprise virtual infrastructure.

H

Microsoft Hyper-V

Microsoft's hypervisor architecture used for server and enterprise virtualization.

X

Xen

A hypervisor architecture used in server and cloud virtualization environments.

K

KVM

Kernel-based Virtual Machine integrates virtualization capabilities with the Linux kernel and is commonly paired with QEMU.

Professional Note: Hyper-V and KVM

Hypervisor classifications can appear more complex in modern platforms. For example, Microsoft Hyper-V uses a privileged parent partition, while KVM integrates virtualization functionality into the Linux kernel. Despite architectural differences from traditional minimalist hypervisors, both are generally treated as Type 1 virtualization technologies in professional infrastructure discussions.

06

Hosted Architecture

Type 2 Hypervisors

A Type 2 hypervisor operates as software on top of a conventional host operating system.

This architecture is also known as hosted virtualization.

Instead of directly replacing the normal host operating system, the virtualization software is installed similarly to another application. The host operating system continues to manage much of the physical hardware, device drivers, user accounts, desktop environment, and general system functions.

Type 2 hypervisors are particularly useful for laboratories, software testing, application development, classroom demonstrations, operating-system experiments, and desktop virtualization.

How Type 2 Works

1

Physical Computer Starts

The computer initializes its physical hardware in the normal manner.

2

Host Operating System Loads

Windows, Linux, macOS, or another host operating system boots and manages the physical computer.

3

Hypervisor Application Starts

The user launches the virtualization software from the host operating system.

4

Virtual Machines Start

The virtualization application creates or starts VMs containing independent guest operating systems.

5

Resources Are Shared

The host operating system, hypervisor software, and virtual machines share available processor, memory, storage, and network resources.

Common Type 2 Platforms

V

Oracle VirtualBox

Desktop virtualization platform frequently used in classrooms, laboratories, development, and testing.

W

VMware Workstation

Desktop virtualization software designed to run multiple guest operating systems on a workstation.

F

VMware Fusion

Desktop virtualization software for running guest environments on supported Mac systems.

P

Parallels Desktop

Hosted virtualization platform commonly associated with desktop virtualization on Mac computers.

07

Architecture

Type 1 vs Type 2 Architecture

The easiest way to understand the difference is to examine the number and position of software layers between the virtual machine and the physical hardware.

KEY DIFFERENCE

Type 1 places the virtualization control layer directly on the server hardware, while Type 2 operates through a host operating system.

08

Operational Flow

How a Virtual Machine Uses Physical Resources

When software inside a virtual machine performs an operation, several layers may participate in translating the virtual request into physical hardware activity.

Example: Virtual Disk Operation

Assume an application inside a virtual machine saves a file. The application communicates with the guest operating system. The guest operating system writes to what appears to be a virtual disk. The hypervisor or associated virtualization storage layer maps that virtual disk operation to actual physical or network-based storage.

The guest operating system does not necessarily need to know the exact physical disk where the information is ultimately stored. This separation is one example of hardware abstraction.

09

Processor Support

Hardware-Assisted Virtualization

Modern processors contain hardware features designed to improve virtual machine execution. These features allow the processor and hypervisor to coordinate privileged operations more efficiently.

Intel

Intel VT-x

Intel VT-x provides processor-level virtualization extensions that assist hypervisors when executing virtual machines.

AMD

AMD-V

AMD-V provides hardware virtualization extensions in supported AMD processors for virtual machine execution.

Why Hardware Assistance Matters

  • Improves execution of privileged guest operating-system instructions.
  • Reduces the amount of software translation required for some virtualization operations.
  • Supports stronger and more efficient memory virtualization mechanisms on modern processors.
  • Enables contemporary hypervisors to run many guest operating systems efficiently.
  • May be required for certain virtualization features and 64-bit guest configurations.
i

BIOS / UEFI Configuration

On some computers, hardware virtualization support must be enabled through BIOS or UEFI firmware configuration before virtualization software can use it.

Infrastructure Evaluation

Performance and Resource Efficiency

Performance is one of the major factors considered when selecting a virtualization architecture. However, performance should be evaluated using the complete system rather than the hypervisor category alone.

CPU

Processor

The hypervisor schedules virtual CPUs onto physical processor cores.

RAM

Memory

Every active VM consumes memory, while the virtualization platform also requires memory.

SSD

Storage

Virtual disks ultimately rely on physical or network-based storage performance.

NET

Network

Virtual switches and virtual network adapters connect virtual workloads to each other and external networks.

Why Type 1 Is Common in Data Centers

Type 1 platforms are commonly engineered specifically for server consolidation and enterprise virtualization. Their architecture typically avoids using a conventional desktop operating system as an intermediate host layer.

This can reduce unnecessary software overhead and allows virtualization infrastructure to be managed as a dedicated computing platform.

Does Type 1 Always Mean Faster?

No. Although Type 1 architecture is generally preferred for large production environments, it is inaccurate to state that every Type 1 configuration will always outperform every Type 2 configuration.

Actual results depend on CPU architecture, available RAM, storage performance, network configuration, guest workload, drivers, virtualization settings, and hypervisor implementation.

Infrastructure Protection

Security and Isolation

Virtualization does not automatically make a system secure. A virtualized environment must be designed, configured, updated, monitored, and protected using appropriate security controls.

01

Physical Security

Protect physical servers, storage systems, and networking equipment.

02

Hypervisor Security

Apply patches, restrict administrative access, disable unnecessary services, and protect management interfaces.

03

Virtual Network Security

Segment networks appropriately and control traffic between virtual machines.

04

Guest Operating System Security

Each VM still requires operating-system updates, identity management, application security, and endpoint protection.

05

Management Security

Protect administrator credentials, management consoles, APIs, backups, and remote-access interfaces.

Type 2 Security Consideration

In Type 2 virtualization, the host operating system is another important security boundary. If the host OS is compromised or incorrectly configured, the virtualization environment may also be placed at risk.

Concept Clarification

Common Misconceptions

MYTH 01

A virtual machine is a physical computer.

Correction:

A virtual machine is a software-defined computing environment that receives virtualized hardware resources from the hypervisor.

MYTH 02

Type 2 virtualization does not use hardware virtualization.

Correction:

Modern hosted virtualization platforms can also use hardware virtualization extensions such as Intel VT-x or AMD-V.

MYTH 03

Virtualization completely eliminates hardware limitations.

Correction:

Virtual machines ultimately depend on finite physical CPU, memory, storage, and networking resources.

MYTH 04

Every Type 1 hypervisor is always faster.

Correction:

Type 1 architecture is generally optimized for production server workloads, but actual performance depends on many architectural and configuration factors.

MYTH 05

A VM does not need security because it is isolated.

Correction:

Guest operating systems and applications require normal security controls, patching, access control, monitoring, and network protection.

Professional Vocabulary

Key Virtualization Terminology

Host
The physical computer or virtualization system providing resources to virtual machines.
Guest
An operating system running inside a virtual machine.
Virtual Machine
A software-defined computer containing virtual hardware and usually a guest operating system.
Hypervisor
Software or system technology that creates and manages virtual machines.
vCPU
A virtual processor allocated to a virtual machine.
vRAM
Memory capacity allocated to a virtual machine from physical host memory.
Virtual Disk
A software-defined storage device presented to a virtual machine.
vNIC
A virtual network interface presented to a virtual machine.
Virtual Switch
A software-based network switching component used to connect virtual interfaces and networks.
Snapshot
A point-in-time representation of a VM's state or storage, depending on the virtualization platform.
Hardware Abstraction
The separation between physical hardware details and the virtual hardware presented to workloads.
Resource Pool
A logical collection of computing resources that can be allocated according to virtualization policies.

Summary

Lesson Review

Remember These Core Concepts

  • Virtualization allows multiple virtual machines to share physical computing resources.
  • The hypervisor is responsible for creating and controlling virtual machine environments.
  • Type 1 hypervisors operate as the primary virtualization layer directly above server hardware.
  • Type 2 hypervisors operate above a conventional host operating system.
  • Type 1 platforms are commonly used for production servers, enterprise infrastructure, and data centers.
  • Type 2 platforms are commonly used for development, testing, education, and workstation virtualization.
  • Modern processors provide hardware virtualization technologies such as Intel VT-x and AMD-V.
  • Virtual machines still depend on the physical CPU, memory, storage, and network resources of the host.
  • Hypervisor selection should consider performance, scalability, security, availability, hardware support, management, and workload requirements.
