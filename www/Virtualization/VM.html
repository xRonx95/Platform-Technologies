Professional Lecture Module

Building Virtual Machines

A virtual machine (VM) is a software-defined computer that runs an operating system and applications while sharing the physical resources of a host computer. This lesson explains how to plan, create, configure, install, secure, test, and maintain virtual machines using commonly used desktop hypervisors such as VirtualBox and VMware Workstation.

01

Foundation

What Does “Building a Virtual Machine” Mean?

Building a virtual machine is the process of creating a software-based computer with its own virtual processor, memory, storage, network adapter, firmware, and operating system. Instead of purchasing another physical computer for every operating system or laboratory exercise, an organization can create multiple isolated virtual machines on one sufficiently powerful host computer.

A VM behaves like an independent computer. It can be started, shut down, restarted, connected to a network, backed up, cloned, and restored. The guest operating system normally sees virtual hardware rather than the host's physical hardware directly. The hypervisor is responsible for coordinating access to the underlying resources.

Teaching point: A virtual machine is not simply a folder containing an operating system. It is a complete logical computer environment whose virtual hardware is managed by virtualization software.
H

Host

The physical computer that provides CPU, memory, storage, and network resources.

HV

Hypervisor

The virtualization layer that creates and controls one or more virtual machines.

G

Guest

The operating system installed inside the VM, such as Windows, Ubuntu, or another OS.

VD

Virtual Disk

A file or set of files that functions as the VM's hard drive or solid-state drive.

Core Concept

Virtual Machine Architecture

The architecture of a desktop virtualization environment can be viewed as a stack. Applications run inside the guest operating system. The guest communicates with virtual devices, while the hypervisor maps those virtual devices to physical host resources.

vCPU A virtual processor presented to the guest operating system.
vRAM Host memory reserved or made available for the running VM.
Virtual Disk A storage file presented to the guest as a hard disk or SSD.
Virtual NIC A software-defined network adapter used by the VM.
Virtual Firmware BIOS or UEFI-like firmware used during the guest boot process.
04

Before the Lab

Host Requirements and Preparation

A successful VM deployment starts with a capable host system. The host must have enough resources to run its own operating system and still provide resources to the guest. Over-allocation can make both the host and the VM slow or unstable.

Recommended Preparation

  • Confirm that hardware virtualization is supported and enabled.
  • Keep sufficient free RAM for the host operating system.
  • Maintain adequate free disk capacity for virtual disks and snapshots.
  • Use an SSD where possible for better virtual disk performance.
  • Download a legitimate operating-system ISO image.
  • Install a supported hypervisor before beginning the exercise.

Avoid Resource Exhaustion

Do not allocate all host processors or nearly all host memory to one VM. The host must remain responsive because the hypervisor itself depends on the host's CPU, memory, storage, and operating-system services.

Step 1

Choose and Open the Hypervisor

Desktop VM creation commonly begins in a Type 2 hypervisor. In a classroom setting, VirtualBox and VMware Workstation are frequently used because they provide graphical wizards for creating and configuring virtual machines.

VirtualBox Workflow

Open VirtualBox, select the command for creating a new virtual machine, then provide the VM name, guest operating-system information, ISO image, memory, processors, and virtual disk settings.

VMware Workflow

Open VMware Workstation, start the New Virtual Machine Wizard, choose the configuration type, select the installation media, name the VM, define storage, and review hardware before finishing.

Step 2

Prepare the Operating-System Installation Media

An ISO image is a file representation of installation media. During VM creation, the hypervisor can attach the ISO to a virtual optical drive so that the VM can boot from it and launch the operating-system installer.

Obtain the ISO

Use an official or authorized source appropriate for the laboratory.

2

Confirm the correct operating-system edition and architecture.

3

Place the ISO in a folder that can be found easily during the VM wizard.

4
Attach It to the VM

Select the ISO when the hypervisor asks for installation media.

Step 3

Create a New Virtual Machine

The creation wizard gathers the information that defines the VM. The exact screens vary by hypervisor version, but the underlying decisions are similar: identity, guest OS, firmware, processors, memory, storage, network, and installation media.

A

Name the VM Clearly

Use a descriptive naming convention such as WIN11-LAB01, UBUNTU-SERVER01, or DB-LAB-MYSQL. A clear name becomes important when many VMs exist on one host.

B

Select the Guest Operating-System Family

Choose the closest matching OS type and version so the hypervisor can apply suitable default hardware and compatibility settings.

C

Select the VM Storage Location

Save the VM on a drive with adequate free space. Keep laboratory VMs in a structured folder so configuration files, disks, and related artifacts are easier to manage.

Step 4

Allocate CPU and Memory

CPU and memory allocation directly affect guest performance and host stability. More resources are not always better. The goal is to provide enough resources for the guest workload while preserving capacity for the host and other VMs.

Memory Guidance

Allocate enough memory to meet the guest OS and application requirements. If the guest continuously uses swap or pagefile space, it may need more RAM.

Processor Guidance

Start conservatively. Increase vCPU count when the workload benefits from it and when the host has sufficient processor capacity.

10

Step 5

Create and Configure Virtual Storage

A virtual disk is typically stored as a file on the host. Inside the guest, however, it appears as a normal disk device. Hypervisors may support dynamically allocated disks, fixed/preallocated disks, multiple disk formats, and several virtual storage controller types.

Dynamically Allocated

The virtual disk file grows as data is written, up to its configured maximum. This can save host storage initially.

Fixed / Preallocated

The requested storage capacity is reserved in advance. It can simplify capacity planning but consumes more host storage immediately.

Important distinction: A virtual disk configured as “100 GB” does not always mean a 100 GB host file is created immediately. The actual host-space behavior depends on the disk allocation method selected.
11

Step 6

Choose the Correct Virtual Network Mode

Virtual networking controls how the guest communicates with the host, other VMs, the local physical network, and the internet. The correct mode depends on the laboratory objective and the required level of isolation.

NAT Useful when the VM needs outbound network access without appearing as a separate device on the physical LAN.
Bridged Connects the VM more directly to the physical network; the guest can receive its own network identity.
Host-Only Creates a network mainly between the host and selected VMs, useful for controlled laboratories.
Internal / Private Allows selected VMs to communicate with one another while remaining isolated from external networks.

Step 7

Boot the VM and Install the Guest Operating System

After the virtual hardware is defined, start the VM. If the ISO image is attached and the boot order is correct, the virtual machine should start the OS installer. From this point, installation is similar to installing the operating system on a physical computer.

01

Power On

Start the newly created VM from the hypervisor.

02

Boot from ISO

Confirm the installer starts from the attached virtual optical media.

03

Partition the Virtual Disk

Install the guest OS onto the VM's virtual disk, not the host's physical system disk.

04

Create the Guest Account

Set the required user account, credentials, hostname, and localization.

05

Complete Installation

Allow setup to finish, reboot, and detach the ISO when appropriate.

13

Step 8

Install Guest Integration Tools

Hypervisors commonly provide integration packages for the guest operating system. In VirtualBox this is commonly associated with Guest Additions, while VMware environments use VMware Tools. These components improve interaction between the guest and host.

Display

Improved graphics support and dynamic resolution changes.

Mouse Integration

Smoother pointer movement between host and guest windows.

Clipboard

Optional copy-and-paste integration when enabled by policy.

Shared Folders

Controlled file sharing between host and guest when required.

Time Synchronization

Helps keep guest time aligned with the virtualization platform.

Drivers

Installs optimized drivers for selected virtual devices.

Security reminder: Convenience features such as shared clipboard, drag-and-drop, and shared folders increase connectivity between the host and guest. Enable only what the laboratory requires.
14

Recovery Point

Use Snapshots Before Risky Changes

A snapshot records a recoverable VM state at a point in time. Snapshots are useful before software installation, configuration experiments, malware-analysis labs, major updates, or student exercises that may change the system significantly.

Do not confuse snapshots with full backups. Snapshots are excellent for short-term rollback and testing, but a robust backup strategy should protect VM data independently from the active VM storage.
15

Lifecycle

Cloning, Templates, and Export

Once a well-configured VM exists, it can often be duplicated rather than rebuilt manually. Cloning is useful in classrooms, development laboratories, test environments, and repeatable demonstrations.

Clone

Create another VM based on an existing VM. Review identity and networking after duplication.

Template Concept

Maintain a clean baseline VM that can be copied for repeated laboratory exercises.

Export / Import

Package a VM in a portable format when supported for transfer to another environment.

16

Protection

Security Considerations

Isolation is one of virtualization's major benefits, but a VM should not be treated as automatically secure. A guest connected to a network can still be attacked, misconfigured, infected, or used to expose services.

01

Patch the guest OS. Apply appropriate security updates.

02

Use strong authentication. Protect guest accounts with appropriate credentials.

03

Limit network exposure. Choose an isolated network when internet or LAN access is unnecessary.

04

Control integrations. Disable clipboard, drag-and-drop, USB, or shared folders when not required.

05

Protect VM files. Anyone who can access the VM's virtual disk may be able to access its data.

06

Use snapshots carefully. Snapshot names should clearly identify purpose and date or stage.

17

Optimization

Performance and Resource Management

VM performance depends on the workload, host hardware, virtual hardware settings, storage speed, and the number of simultaneously active VMs. Performance problems should be investigated systematically instead of solved by immediately assigning more resources.

High Guest CPU

Check active applications and whether more vCPU is justified.

Memory Pressure

Check host and guest memory usage before increasing VM RAM.

Slow Disk

Review host free space, disk type, storage speed, and snapshot growth.

Slow Network

Review network mode, host adapter status, DNS, and guest configuration.

Problem Solving

Common VM Problems and Checks

Problem Possible Cause Recommended Check
64-bit guest option missing Hardware virtualization unavailable or disabled; host conflict Check firmware virtualization support and host virtualization settings.
VM will not boot installer ISO not attached or boot order incorrect Review virtual optical drive and boot sequence.
Guest is very slow Insufficient or excessive resource allocation; slow storage Review host load, guest RAM, vCPU count, and storage activity.
No network access Wrong network mode or adapter configuration Verify virtual NIC is enabled and review NAT/bridged/host-only settings.
Disk becomes very large Guest data growth or many snapshots Review virtual disk usage, snapshots, and host free space.
Screen resolution is limited Guest integration tools missing Install or update the hypervisor's guest tools.

Professional Practice

Virtual Machine Best Practices

Identify OS, role, and laboratory purpose in the VM name.

02

Start Small

Begin with sensible resource allocation and increase only when justified.

03

Separate Baseline and Working Copies

Keep a clean source VM for repeatable laboratory deployment.

Document Configuration

Record CPU, RAM, disk, network mode, guest OS, and snapshot purpose.

Conclusion

Lesson Summary

Building a virtual machine is a structured engineering task. It begins by defining the workload and selecting a hypervisor, then continues through guest OS selection, CPU and memory allocation, virtual disk creation, network design, installation, guest integration, testing, security, snapshot management, and ongoing maintenance.

The most important skill is not memorizing a particular wizard. A competent virtualization practitioner understands what each VM component represents and can make appropriate design decisions even when the interface changes between VirtualBox, VMware, or another virtualization platform.

Key takeaway: Build virtual machines deliberately: plan the workload, allocate resources responsibly, isolate networks when appropriate, validate the guest after installation, and maintain recoverable baseline states.
