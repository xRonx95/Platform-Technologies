Lesson Introduction

Managing More Than One Container

A modern application rarely consists of only one program. A web application might require a web server, application server, database, caching server, and other supporting services.

Docker can run each component in a separate container. However, manually creating every container with individual docker run commands quickly becomes difficult to manage.

Without Docker Compose

  • Run containers individually.
  • Create networks manually.
  • Configure ports manually.
  • Create volumes manually.
  • Repeat long commands.
  • Remember the correct startup order.

With Docker Compose

  • Describe the application in one YAML file.
  • Start multiple containers together.
  • Create networks automatically.
  • Manage persistent storage.
  • Configure environment variables.
  • Stop the entire application easily.

Topic 2

What is Docker Compose?

Definition

Docker Compose is a tool for defining and running applications that use multiple Docker containers.

Instead of entering several long Docker commands manually, the application's services and configuration are stored inside a YAML file, usually named:

compose.yaml

You can then start the entire application with one command:

Terminal 
docker compose up

Docker Compose reads the configuration and creates the required containers, networks, and volumes.

Docker Compose Architecture
compose.yaml Application Definition
→
Docker Compose Orchestration
→
Web Container
Database Container
Cache Container
Topic 3

Docker Images in Compose

A Docker image contains the files, runtime, libraries, and configuration necessary to create a container.

Dockerfile defines how an image is built
→
Image application template
→
Container running image instance

Using an Existing Image

The image property tells Docker Compose which Docker image should be used for the service.

compose.yaml
services:

  web:
    image: nginx:alpine

  database:
    image: postgres:alpine
Property
Meaning
nginx
Name of the Docker image.
alpine
Image tag or variant.
image:
Specifies the image used to create the container.

Building Your Own Image

When your application contains its own Dockerfile, Compose can build an image automatically.

compose.yaml
services:

  web:
    build: .
    ports:
      - "5000:5000"

The period (.) means Docker should look for the Dockerfile inside the current directory.

Teaching Tip: An image is not the same as a container. The image is the reusable template, while the container is the running instance created from that image.
Topic 4

Services and Containers

The main section of a Compose file is services. Each service normally represents one component of the application.

Basic Compose Structure
services:

  web:
    image: nginx:alpine

  database:
    image: postgres:alpine

  cache:
    image: redis:alpine

This application has three services:

WEB

web

Runs the web server or application.

DB

database

Stores application information.

CACHE

cache

Provides temporary high-speed data storage.

Important:

The service name can also act as a hostname between containers on the Compose network.

For example, the web container can connect to the database using the hostname database.

Topic 5

Understanding compose.yaml

Docker Compose uses YAML syntax. YAML depends heavily on indentation, so spacing must be consistent.

compose.yaml
services:

  web:
    image: nginx:alpine
    ports:
      - "8080:80"

  database:
    image: postgres:alpine
    environment:
      POSTGRES_DB: school
      POSTGRES_USER: student
      POSTGRES_PASSWORD: secret

Important YAML Rules

1 Use spaces for indentation.
2 Avoid tabs.
3 Child properties must be indented.
4 Lists begin with a hyphen (-).
5 Key-value mappings use a colon (:).
Topic 6

Configuring Ports

Containers run inside their own isolated environment. Port mapping allows a service inside a container to be accessed from the host computer.

Port Mapping
services:

  web:
    image: nginx:alpine

    ports:
      - "8080:80"
Your Computer Port 8080
→
Nginx Container Port 80
Syntax
"HOST_PORT:CONTAINER_PORT"

Therefore:

http://localhost:8080

sends traffic to port 80 inside the container.

Topic 7

Persistent Storage with Volumes

Containers are designed to be replaceable. If a database container is deleted, its internal data can also disappear unless persistent storage is used.

Docker Volume

A Docker volume provides persistent storage that exists independently from the container using it.

Database Volume Example
services:

  database:
    image: postgres:alpine

    volumes:
      - database_data:/var/lib/postgresql/data


volumes:
  database_data:
PostgreSQL Container /var/lib/postgresql/data
⇄
Docker Volume database_data

If the database container is recreated, the data stored in database_data can remain available.

Topic 8

Docker Compose Networks

Docker Compose automatically creates a network for the application. Services inside the same Compose project can usually communicate by using their service names.

Docker Compose Network
web Application
database PostgreSQL
cache Redis

Example Database Connection

Connection Information
Database Host: database
Database Port: 5432
Database Name: school
Username: student
Common Mistake

Inside the web container, localhost refers to that container itself. It does not refer to the database container.

Use the Compose service name such as database.

Topic 9

Environment Variables

Environment variables allow configuration values to be passed to containers.

Environment Variables
services:

  database:
    image: postgres:alpine

    environment:
      POSTGRES_DB: school
      POSTGRES_USER: student
      POSTGRES_PASSWORD: student123

Applications can also receive configuration values:

Application Environment
services:

  web:
    build: .

    environment:
      DATABASE_HOST: database
      DATABASE_PORT: 5432
      DATABASE_NAME: school
      DATABASE_USER: student
      DATABASE_PASSWORD: student123
Security Reminder

Avoid committing production passwords, API keys, and other secrets directly into public source-code repositories.

Topic 10

Service Dependencies with depends_on

An application may depend on another service. For example, a web application may require its database.

depends_on Example
services:

  web:
    build: .

    depends_on:
      - database


  database:
    image: postgres:alpine

In this example, the web service depends on the database service.

Health Check Example

A health check can help determine whether a service is actually ready to accept connections.

Database Health Check
services:

  database:
    image: postgres:alpine

    environment:
      POSTGRES_DB: school
      POSTGRES_USER: student
      POSTGRES_PASSWORD: student123

    healthcheck:
      test:
        - CMD-SHELL
        - pg_isready -U student -d school
      interval: 5s
      timeout: 5s
      retries: 5


  web:
    build: .

    depends_on:
      database:
        condition: service_healthy
Topic 11

Complete Multi-Container Application

In this practical example, we will create a simple application with:

1

Web Application

Python Flask application.

2

Redis

Stores the page visit counter.

Project Folder Structure

docker-compose-demo/
│
├── compose.yaml
├── Dockerfile
├── requirements.txt
└── app.py

Step 1: Create app.py

app.py
from flask import Flask
import redis

app = Flask(__name__)

cache = redis.Redis(
    host="redis",
    port=6379
)


@app.route("/")
def home():

    count = cache.incr("visits")

    return f"""
    <h1>Docker Compose Application</h1>
    <p>This page has been visited {count} times.</p>
    """


if __name__ == "__main__":

    app.run(
        host="0.0.0.0",
        port=5000
    )

Step 2: Create requirements.txt

requirements.txt
flask
redis

Step 3: Create the Dockerfile

Dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

EXPOSE 5000

CMD ["python", "app.py"]

Step 4: Create compose.yaml

compose.yaml
services:

  web:
    build: .

    ports:
      - "5000:5000"

    depends_on:
      - redis


  redis:
    image: redis:alpine

    volumes:
      - redis_data:/data


volumes:
  redis_data:

Step 5: Build and Start the Application

Terminal 
docker compose up --build

Step 6: Open the Application

Open a web browser and visit:

http://localhost:5000
localhost:5000

Docker Compose Application

This page has been visited 1 times.

What Happened?

1
Compose reads compose.yaml.

Docker identifies the web and Redis services.

2
The web image is built.

Docker uses the Dockerfile to create the application image.

3
The Redis image is downloaded.

Docker retrieves the image when it is not already available locally.

4
A network is created.

The containers can communicate through their service names.

5
The containers start.

Flask communicates with Redis using the hostname redis.

Topic 12

Essential Docker Compose Commands

Start services

Creates and starts the containers.

docker compose up

Start in background

Runs the containers in detached mode.

docker compose up -d

Build before starting

Rebuilds application images.

docker compose up --build

List containers

Displays the Compose services and their status.

docker compose ps

View logs

Displays logs from the containers.

docker compose logs

Follow logs

Continuously displays new log output.

docker compose logs -f

Restart services

Restarts the Compose containers.

docker compose restart

Stop services

Stops containers without removing them.

docker compose stop

Start stopped services

Starts existing stopped containers.

docker compose start

Remove application containers

Stops and removes Compose containers and networks.

docker compose down

Remove volumes too

Stops the application and deletes its named volumes.

docker compose down -v

Validate configuration

Checks and displays the resolved Compose configuration.

docker compose config
Be Careful: docker compose down -v

removes named volumes associated with the Compose application. Database information stored exclusively in those volumes can be deleted.

Topic 15

Common Problems and Troubleshooting

Port Already in Use

Another application is already using the host port.

ports:
  - "8081:80"

Change the host port to another available port.

Container Exits Immediately

Check the application logs.

docker compose logs

Containers Cannot Communicate

Verify that the application uses the Compose service name instead of localhost.

DATABASE_HOST=database

Old Application Code Appears

Rebuild the application image.

docker compose up --build

Database Is Not Ready

Configure a health check and dependency condition.

condition: service_healthy

Check Current Services

Display the running Compose containers.

docker compose ps
Topic 16

Docker Compose Best Practices

✓
Use meaningful service names.

Examples: web, database, cache.

✓
Use specific image tags when appropriate.

Image versioning can make deployments more predictable.

✓
Use volumes for persistent data.

Database information should not depend solely on the writable container layer.

✓
Do not expose unnecessary ports.

Only publish services that need access from outside the Docker network.

✓
Protect sensitive configuration.

Do not publish real production credentials in source-code repositories.

✓
Validate the Compose configuration.

Use docker compose config before deployment.

✓
Monitor container logs.

Use docker compose logs -f during debugging.

Topic 17

Docker vs Docker Compose

Feature Docker Docker Compose
Main Purpose Manage containers individually. Manage applications consisting of multiple services.
Configuration CLI commands and Dockerfiles. YAML configuration.
Start Application Multiple commands may be required. docker compose up
Networking Can be configured manually. Application network is normally created automatically.
Volumes Can be created manually. Can be declared directly in Compose.
Multi-Container Apps Possible but more manual. Designed specifically for this purpose.
