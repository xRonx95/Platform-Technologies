01

Introduction to Docker

Docker is a platform used to build, package, distribute, and run applications inside lightweight isolated environments called containers.

Instead of manually installing every dependency required by an application on every computer, developers can package the application together with its dependencies into a Docker image.

Simple Definition

Docker allows developers to package an application together with everything it needs so that the application can run consistently on different computers and servers.

Example Problem

Imagine that a developer creates a Node.js application using:

  • Node.js version 22
  • Specific NPM packages
  • Environment variables
  • A particular Linux configuration

The application works on the developer's computer but fails when transferred to another machine because the other machine has different software versions.

Application
+
Dependencies
+
Configuration
→
Docker Image

Docker solves this problem by providing a consistent environment for the application.

02

Why Do We Use Docker?

📦

Portability

A container can run on a developer computer, testing server, cloud server, or other compatible Docker environment.

⚡

Fast Deployment

Containers normally start much faster than traditional virtual machines.

🔒

Isolation

Applications can run in separate containers, reducing conflicts between dependencies.

🔁

Consistency

Developers and servers can use the same image, reducing configuration differences.

📈

Scalability

Multiple containers can be created when an application requires additional capacity.

☁️

Cloud Friendly

Docker containers are widely used with AWS, Microsoft Azure, Google Cloud, Kubernetes, and other platforms.

Compare

Docker Containers vs Virtual Machines

Feature Docker Container Virtual Machine
Operating System Shares the host kernel Has a complete guest OS
Startup Usually seconds Usually slower
Storage Size Usually smaller Usually larger
Resource Usage Lower Higher
Isolation Process-level isolation Full OS-level virtualization
Typical Use Application deployment Complete virtual computers
Important: Containers and virtual machines are not exactly the same. A container normally shares the operating system kernel of its host, while a VM includes its own guest operating system.

Docker Images

A Docker image is a read-only package containing the application, dependencies, libraries, and configuration needed to create a container.

Think of an Image as a Template

An image is similar to a blueprint. The blueprint itself is not the running application. Docker uses the blueprint to create one or more running containers.

06

Docker Ports

Containers are isolated from the host system. If a container runs a web server, users normally need a published port to access the application from outside the container.

🌐 Browser localhost:8080
→
HOST Port 8080
→
CONTAINER Port 80

Port Mapping Syntax

-p HOST_PORT:CONTAINER_PORT

Example

Terminal Docker 
docker run -d -p 8080:80 --name web nginx
8080 Host computer port
80 Nginx container port

After running the command, open a browser and visit:

http://localhost:8080

Important Rule

The number before the colon is the host port. The number after the colon is the container port.

8080:80

HOST PORT → CONTAINER PORT

07

Docker Volumes

By default, data created inside a container belongs to that container's writable layer. Important application data should not depend solely on that temporary container layer.

Docker provides volumes for persistent data storage.

Without Persistent Storage

If application data exists only inside the container's writable layer, removing that container also removes that container-specific data.

📦 MySQL Container
↕
💾 Docker Volume Persistent Data

Create a Volume

Terminal Docker 
docker volume create student-data

List Volumes

Terminal Docker 
docker volume ls

Attach a Volume to a Container

Terminal Docker 
docker run -d \
--name database \
-v student-data:/var/lib/mysql \
mysql

The general volume syntax is:

-v VOLUME_NAME:CONTAINER_PATH

Why Volumes Are Important

  • Preserve important application data.
  • Allow containers to be replaced more safely.
  • Separate application data from the container lifecycle.
  • Useful for databases, uploaded files, and other persistent application data.
08

Introduction to Dockerfile

A Dockerfile is a text file containing instructions Docker uses to build an image.

Simple HTML Project

📁 my-website
📄 index.html
📄 Dockerfile

Example Dockerfile

Dockerfile Docker 
FROM nginx:alpine

COPY index.html /usr/share/nginx/html/index.html

EXPOSE 80
FROM

Selects the base image.

COPY

Copies files into the image.

EXPOSE

Documents the port the application expects to listen on.

Build the Image

Terminal Docker 
docker build -t my-website .
docker build Build an image
-t my-website Name/tag the image
. Use the current directory as build context

Run the Image

Terminal Docker 
docker run -d -p 8080:80 --name my-site my-website

Essential Docker Commands

Command Purpose
docker --version Display installed Docker version.
docker pull nginx Download an image.
docker images Display local images.
docker run nginx Create and start a container.
docker ps Show running containers.
docker ps -a Show all containers.
docker stop NAME Stop a running container.
docker start NAME Start an existing stopped container.
docker restart NAME Restart a container.
docker rm NAME Remove a stopped container.
docker rmi IMAGE Remove a Docker image.
docker logs NAME Display logs generated by a container.
docker exec -it NAME sh Open an interactive shell when the container provides sh.
docker volume ls Display Docker volumes.
docker inspect NAME Display detailed Docker object information.

Example

Complete Docker Example

The following example starts an Nginx web server named school-web and exposes it through port 8080.

Step 1 — Download Terminal 
docker pull nginx
Step 2 — Run Terminal 
docker run -d -p 8080:80 --name school-web nginx
Step 3 — Verify Terminal 
docker ps
Step 4 — Browser URL 
http://localhost:8080
Step 5 — Stop Terminal 
docker stop school-web
Step 6 — Remove Terminal 
docker rm school-web

12

Basic Docker Best Practices

01

Use Trusted Images

Prefer official or otherwise trusted images from reputable registries.

02

Use Specific Tags

For reproducible deployments, prefer a required version tag rather than relying only on latest.

03

Keep Images Small

Use appropriate lightweight base images when they satisfy application requirements.

04

Protect Secrets

Do not permanently place passwords or API keys inside Docker images or public source code.

05

Persist Important Data

Use Docker volumes or other appropriate persistent storage for important application data.

06

Remove Unused Resources

Periodically review unnecessary stopped containers and unused images.

14

Knowledge Check

Ask students to answer the following questions before checking the answers.

1. What is Docker?
Docker is a platform for building, packaging, distributing, and running applications in containers.
2. What is the difference between an image and a container?
An image is a template, while a container is a runnable instance created from that image.
3. What does docker pull nginx do?
It downloads the Nginx Docker image from a configured registry.
4. What does docker ps display?
It displays currently running containers.
5. In -p 8080:80, which number is the host port?
Port 8080 is the host port. Port 80 is the container port.
6. Why are Docker volumes used?
Volumes provide persistent storage that can remain available independently of a particular container's writable layer.
7. What does the -d option mean?
It starts the container in detached mode so it runs in the background.
8. Which command stops a container named web?
docker stop web
9. What file contains instructions for building a Docker image?
A Dockerfile.
10. What is the basic Docker workflow?
Create the application → create a Dockerfile → build an image → run a container → publish required ports → test or deploy the application.
Discussion

Classroom Discussion Questions

  1. Why might Docker reduce the problem of "it works on my computer"?
  2. Why is an image different from a running container?
  3. What could happen if a database stores important data only inside a temporary container?
  4. Why is port mapping necessary for many containerized web applications?
  5. When might a virtual machine be preferable to a container?
  6. How can Docker help when deploying an application to a cloud platform?
