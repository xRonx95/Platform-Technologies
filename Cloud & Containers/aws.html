REVIEW

What Is Cloud Computing?

☁

Cloud Computing

Cloud computing is the delivery of computing resources such as servers, storage, databases, networking, software, and application platforms over a network, typically the Internet.

Instead of purchasing and maintaining every physical server yourself, you can obtain computing resources from a cloud service provider. Resources can usually be provisioned when they are needed and scaled according to demand.

⚡

On Demand

Resources can be created when they are required instead of waiting for new physical hardware.

↕

Scalable

Computing resources can grow or shrink based on application demand.

₱

Usage Based

Many cloud services use consumption-based pricing where organizations pay for the resources they consume.

🌐

Accessible

Cloud resources can be managed remotely through web consoles, APIs, command-line tools, and development tools.

03
CLOUD PROVIDERS

What Is a Cloud Service Provider?

A Cloud Service Provider (CSP) is a company that operates cloud infrastructure and makes computing resources available to customers.

🏢 Cloud Provider Operates data centers
→
☁ Cloud Services Compute, storage, database
→
💻 Customer Uses the resources
Teacher's Explanation

Think of cloud computing like renting computing resources. You do not necessarily need to own the physical server. Instead, a provider maintains large data centers while customers select and use the services they need.

PLATFORM COMPARISON

Equivalent Services

The three providers often offer services that solve similar technical problems, although their exact capabilities, configuration, terminology, and pricing models differ.

Category AWS Microsoft Azure Google Cloud
Virtual Machines Amazon EC2 Azure Virtual Machines Compute Engine
Object Storage Amazon S3 Azure Blob Storage Cloud Storage
Managed Relational Database Amazon RDS Azure SQL Database Cloud SQL
Managed Application Platform AWS Elastic Beanstalk Azure App Service App Engine
Serverless Functions AWS Lambda Azure Functions Cloud Run functions
Managed Kubernetes Amazon EKS Azure Kubernetes Service Google Kubernetes Engine
Container Platform Amazon ECS / AWS Fargate Azure Container Apps / AKS Cloud Run / GKE
Important

Equivalent does not mean identical. Two cloud services may belong to the same category but differ in features, supported technologies, management responsibility, pricing, performance, and integration.

CLOUD SERVICE MODELS

Where Do These Services Fit?

IaaS

Infrastructure as a Service

Provides infrastructure such as virtual machines, networking, and storage. Customers maintain more control over the operating system and applications.

Amazon EC2 Azure Virtual Machines Compute Engine
PaaS

Platform as a Service

Provides a managed platform for developing and deploying applications while reducing the need to manage the underlying infrastructure.

AWS Elastic Beanstalk Azure App Service Google App Engine
SaaS

Software as a Service

Provides complete applications that are accessed and used by customers while the provider manages the application and its supporting infrastructure.

Microsoft 365 Google Workspace Online CRM Systems
FaaS

Function as a Service

Developers deploy individual functions that execute when requests or events occur without directly managing traditional servers.

AWS Lambda Azure Functions Cloud Run functions
CaaS

Containers as a Service

Provides cloud infrastructure and management capabilities designed for containerized applications.

Amazon ECS / EKS Azure AKS Google GKE

Does Serverless Mean No Servers?

No.

AWS Lambda

DEPLOYMENT MODELS

Public, Private, Hybrid & Multi-Cloud

🌍

Public Cloud

Computing resources are delivered using infrastructure operated by a public cloud provider.

Example Application hosted entirely on AWS.
🏢

Private Cloud

Cloud infrastructure is dedicated to a particular organization.

Example An organization's internal cloud environment.
🔗

Hybrid Cloud

Combines private or on-premises infrastructure with public cloud resources.

Example Local database plus cloud-hosted web services.
☁☁

Multi-Cloud

Uses cloud services from more than one cloud provider.

Example Using both Azure and Google Cloud services.

DECISION MAKING

How Do We Choose a Cloud Platform?

There is no single cloud platform that is always the correct choice. Organizations should evaluate their technical and business requirements.

01

Application Requirements

What operating system, programming languages, frameworks, databases, and services are required?

02

Cost

What resources will be consumed and what pricing model is appropriate for the workload?

03

Scalability

Can the platform efficiently handle changes in traffic and workload demand?

04

Region & Availability

Are the required services available in regions appropriate for the organization and its users?

05

Security

What identity, access control, encryption, network security, logging, and compliance capabilities are required?

06

Team Skills

Which technologies and cloud platforms does the development or IT team already understand?

PRACTICAL APPLICATION

Which Service Would You Choose?

Scenario 1

You need full control of a Linux server.

You need to install your own operating-system packages and configure the server manually.

Amazon EC2 Azure Virtual Machines Compute Engine
Recommended model: IaaS
Scenario 2

You want to deploy a web application quickly.

Your team wants to concentrate on programming instead of managing the operating system.

Elastic Beanstalk Azure App Service Google App Engine
Recommended model: PaaS
Scenario 3

You have a Docker application.

The application is already packaged as a container and needs cloud deployment.

Amazon ECS / EKS Azure Container Apps / AKS Cloud Run / GKE
Recommended model: Container Platform
Scenario 4

Code should execute only when an event occurs.

For example, code should execute whenever a user uploads a file.

AWS Lambda Azure Functions Cloud Run functions
Recommended model: FaaS / Serverless

LESSON SUMMARY

Key Takeaways

01

AWS, Microsoft Azure, and Google Cloud are major public cloud computing platforms.

02

All three provide services for compute, storage, databases, networking, containers, serverless computing, security, and other workloads.

03

IaaS provides infrastructure, PaaS provides application platforms, and SaaS provides complete applications.

04

Serverless computing reduces direct infrastructure management but does not mean that physical servers no longer exist.

05

Containers can be deployed through managed cloud container and Kubernetes services such as ECS, EKS, AKS, GKE, and Cloud Run.

06

Selecting a cloud platform depends on application requirements, cost, scalability, security, available regions, integrations, and team expertise.

REMEMBER

AWS, Azure, and Google Cloud solve many of the same problems using different service names.

Do not memorize only the product names. Understand the problem each cloud service solves. Once you understand compute, storage, databases, networking, PaaS, containers, and serverless computing, comparing cloud providers becomes much easier.
