TOPIC 02

What Is Linux?

Linux is the kernel at the center of many operating systems. In everyday conversation, people often use the word “Linux” to describe a complete operating system distribution that combines the Linux kernel with system utilities, libraries, package-management tools, applications, and a user interface.

Simple Classroom Definition

Linux is the core software that manages hardware resources and allows programs to communicate with a computer. A Linux distribution packages that kernel with the additional software needed to create a usable operating system.

Why Linux Matters in Cloud Computing

Linux is widely used on servers because it is highly configurable, scriptable, automation-friendly, and well suited to remote administration. Cloud engineers frequently interact with Linux systems through secure shell sessions rather than through a desktop interface.

Linux Is More Than a Desktop OS

  • Servers: web servers, database servers, DNS servers, and application servers.
  • Cloud virtual machines: compute instances in public and private clouds.
  • Containers: many container images use Linux user-space environments.
  • Networking: routers, firewalls, appliances, and infrastructure services.
  • Development: compilers, Git, scripting tools, CI/CD systems, and DevOps workflows.
  • Embedded systems: appliances, IoT devices, and specialized hardware.
Teaching point: The kernel is not the same thing as the shell. The kernel manages system resources; the shell interprets commands from the user.
TOPIC 03

Understanding Linux Architecture

Students understand Linux more easily when the operating system is viewed as layers. A command typed by the user travels through user-space tools before the kernel performs the requested operation on hardware or virtual resources.

Layer 5 Applications & User Tools Editors, browsers, compilers, Git, cloud CLIs
↓
Layer 4 Shell / Command Interpreter Bash, Zsh, Fish
↓
Layer 3 System Libraries & Utilities Core utilities, shared libraries, service tools
↓
Layer 2 Linux Kernel Processes, memory, devices, filesystem, networking
↓
Layer 1 Physical or Virtual Hardware CPU, RAM, disks, NICs, virtual devices

Kernel

Controls low-level resources such as process scheduling, memory, storage devices, drivers, and network interfaces.

User Space

Contains applications and utilities that run outside the kernel, including shells, editors, package managers, and services.

System Calls

Provide controlled interfaces that allow applications to request services from the kernel.

TOPIC 04

Linux Distributions

A Linux distribution (distro) is a complete operating system assembled around the Linux kernel. Distros differ in package management, release policy, default software, support model, and intended audience.

Ubuntu

A widely used Debian-family distribution for desktops, servers, cloud workloads, development, and learning environments.

  • Family: Debian
  • Packages: .deb
  • Common manager: apt
  • Strong cloud/server presence

Debian

A community-developed free operating system known for broad architecture support and a strong emphasis on stability.

  • Family: Debian
  • Packages: .deb
  • Common manager: apt
  • Popular server foundation

Fedora

A community Linux platform focused on current open-source technologies and commonly used by developers and administrators.

  • Family: Red Hat ecosystem
  • Packages: .rpm
  • Common manager: dnf
  • Developer-oriented workstation options

Red Hat Enterprise Linux

A commercially supported enterprise distribution designed for production infrastructure, servers, applications, and regulated environments.

  • Family: Red Hat
  • Packages: .rpm
  • Common manager: dnf
  • Enterprise support lifecycle

Arch Linux

A rolling-release distribution emphasizing simplicity, user control, and hands-on configuration.

  • Family: Independent
  • Packages: .pkg.tar.zst
  • Common manager: pacman
  • Best for experienced learners

Alpine Linux

A compact distribution frequently encountered in lightweight environments and container images.

  • Family: Independent
  • Packages: .apk
  • Common manager: apk
  • Small footprint

TOPIC 05

How to Choose a Linux Distribution

There is no single “best” distribution for every situation. The correct choice depends on workload requirements, support needs, team knowledge, package availability, release policy, and compatibility.

1

Define the workload

Desktop, web server, database, cloud VM, container image, security lab, or embedded system?

2

Check support needs

Will the organization require long-term security updates, vendor support, and certification?

3

Review software availability

Confirm that required packages, runtimes, drivers, and repositories are supported.

4

Consider team skills

A familiar distribution reduces operational errors and speeds troubleshooting.

Recommended classroom approach: Use Ubuntu or Debian for introductory command-line lessons, then demonstrate Fedora/RHEL-family commands so students understand that Linux concepts are portable even when package tools differ.
TOPIC 06

The Linux Filesystem Hierarchy

Linux uses a single directory tree that begins at /, called the root directory. Disks and filesystems are mounted into locations inside this tree.

/
  • /home — regular users' home directories
  • /root — root user's home directory
  • /etc — system-wide configuration
  • /var — variable data such as logs and caches
  • /usr — applications, libraries, documentation
  • /bin — essential command binaries
  • /tmp — temporary files
  • /dev — device representations
  • /proc — process and kernel information interface
  • /mnt and /media — common mount locations
Important: Linux paths are case-sensitive. Report.txt, report.txt, and REPORT.txt can be three different filenames.

Absolute vs. Relative Paths

Absolute Path

Starts from the root directory and identifies a complete location.

/home/student/projects/cloud-notes.txt

Relative Path

Starts from the current working directory.

projects/cloud-notes.txt
TOPIC 07

Shell vs. Terminal

Students often use these words interchangeably, but they describe different components.

Shell

A program that reads commands and starts programs. Bash is a common Linux shell. Other shells include Zsh and Fish.

Terminal
student@server:~$ echo "Hello Linux"
Hello Linux

Terminal Emulator

The graphical or text interface in which a shell session is displayed. Examples include GNOME Terminal, Konsole, Windows Terminal, and remote SSH clients.

Reading a Command Prompt

student@cloud-server:~/projects$
studentCurrent user @Separator cloud-serverHostname ~/projectsCurrent directory $Normal-user prompt
A prompt ending in # commonly indicates a root shell. Students should not assume root access is required for normal work.
TOPIC 08

Essential Navigation Commands

Navigation is the first practical skill students should master because most later tasks depend on knowing where they are in the filesystem.

pwd

Print working directory

Shows the absolute path of the current directory.

ls

List directory contents

Displays files and directories.

ls -la

Detailed listing

Shows hidden files, permissions, ownership, size, and metadata.

cd /path

Change directory

Moves the shell to another directory.

cd ..

Move to parent

Moves one directory level upward.

cd ~

Go to home

Returns to the current user's home directory.

Step-by-Step Demonstration

1

Identify your current location

$ pwd
/home/student

Never assume the current directory. Confirm it before manipulating files.

2

Inspect available files and directories

$ ls -la

The -l option uses a long listing; -a includes hidden entries.

3

Move into a directory

$ cd Documents
$ pwd
/home/student/Documents
4

Return home

$ cd ~
TOPIC 09

Creating and Managing Files

Shell commands can create, copy, move, rename, inspect, and remove files. Students should always verify a path before using destructive commands.

CommandPurposeExample
touchCreate an empty file or update its timestamptouch notes.txt
mkdirCreate a directorymkdir cloud-lab
mkdir -pCreate nested directoriesmkdir -p project/logs
cpCopy a filecp notes.txt backup.txt
cp -rCopy directories recursivelycp -r project project-backup
mvMove or renamemv old.txt new.txt
rmRemove a filerm old.txt

TOPIC 10

Reading, Searching, and Filtering Text

Linux administration depends heavily on text: configuration files, logs, command output, and structured text streams. Shell tools make these data sources easy to inspect.

head

First lines

head -n 10 file.txt

tail

Last lines

tail -n 20 file.txt

tail -f

Follow a file

Useful for watching logs as new lines are written.

grep

Search text

grep "error" app.log

find

Find filesystem entries

find . -name "*.log"

wc

Count text

wc -l access.log counts lines.

sort

Sort lines

sort names.txt

uniq

Collapse adjacent duplicates

Often used after sort.

Example: Find Error Messages in a Log

$ grep -i "error" application.log
ERROR database connection failed
ERROR retry limit reached

The -i option performs a case-insensitive match. In real troubleshooting, students should inspect surrounding context instead of assuming every line containing “error” identifies the root cause.

TOPIC 11

Linux File Permissions

Linux permission controls determine who can read, modify, or execute a file. Basic discretionary permissions are expressed for the owner, group, and others. 

-rwxr-xr-- 1 student developers 2048 Aug 17 script.sh
-Type
rwxOwner
r-xGroup
r--Others

r — Read

Allows file content to be read. For a directory, allows listing entries when combined appropriately.

w — Write

Allows file content to be changed. Directory write permission affects entry creation/removal.

x — Execute

Allows executable files to run. On directories, it controls traversal/search access.

Changing Permissions

# Add execute permission for the owner
$ chmod u+x deploy.sh

# Symbolic permission example
$ chmod g-w report.txt

# Numeric permission example
$ chmod 750 deploy.sh
NumberPermissionMeaning
4rRead
2wWrite
1xExecute
7rwx4 + 2 + 1
5r-x4 + 1
0---No basic permissions
Do not teach chmod 777 as a universal fix. It grants broad permissions and often hides an ownership or deployment design problem. Use the minimum permissions required.
TOPIC 12

Users, Groups, Root, and sudo

Linux is a multi-user operating system. User accounts and groups help separate responsibilities and protect files, processes, and administrative functions.

whoami

Current identity

Displays the current effective username.

id

User and groups

Shows numeric user/group IDs and memberships.

groups

Group membership

Lists groups associated with the user.

passwd

Password management

Changes a user's password when permitted.

sudo

Elevated command

Runs an authorized command with elevated privileges according to policy.

su

Switch user

Starts a shell as another user when authentication and policy allow.

Why sudo Matters

Administrative operations such as installing packages or changing protected configuration may require elevated privileges. Rather than performing all work as root, administrators generally use normal user accounts and elevate only the commands that require it. 

$ sudo apt update
[sudo] password for student:
...
Least privilege: Give users and processes only the permissions required to perform their intended tasks.
TOPIC 13

Processes and Services

A process is a running program. Administrators need to inspect processes, identify resource usage, stop malfunctioning programs, and manage background services.

ps aux

Process snapshot

Shows detailed information about running processes.

top

Live process view

Interactive CPU and memory activity.

kill PID

Send a signal

Requests a process to terminate or handle another signal.

pkill name

Signal by name

Targets processes matching a name/pattern.

systemctl status

Service status

Checks a systemd-managed service.

journalctl

System logs

Queries logs collected by systemd-journald.

Service Administration Example

# Check service status
$ systemctl status ssh

# Start a service (requires appropriate privilege)
$ sudo systemctl start ssh

# Configure a service to start at boot
$ sudo systemctl enable ssh

# View recent service logs
$ journalctl -u ssh --since "30 minutes ago"

Service names vary by distribution and installed package. For example, SSH server services may appear under names such as ssh or sshd.

TOPIC 14

Linux Networking Fundamentals

Cloud engineers troubleshoot Linux networking from the command line. Students should understand interfaces, IP addresses, routes, DNS resolution, sockets, and connectivity tests.

ip addr

IP addresses

Displays network interfaces and assigned addresses.

ip route

Routing table

Shows where network traffic will be sent.

ping

Reachability test

Sends ICMP echo requests when permitted by the network.

ss -tulpn

Listening sockets

Displays TCP/UDP sockets and associated processes when permitted.

curl

HTTP/API testing

Transfers data using URLs and is useful for service checks.

hostname

Host identity

Displays or helps inspect the system hostname.

Four-Step Connectivity Check

1

Check interface state

$ ip addr
2

Check routing

$ ip route
3

Test name resolution/service URL

$ curl -I https://example.com
4

Inspect local listeners

$ ss -tulpn
TOPIC 15

Package Management

Package managers install, upgrade, remove, and track software. The command depends on the distribution family.

Debian / Ubuntu Family

# Refresh package metadata
sudo apt update

# Install a package
sudo apt install nginx

# Upgrade installed packages
sudo apt upgrade

# Remove a package
sudo apt remove nginx

Fedora / RHEL Family

# Refresh/check metadata
sudo dnf check-update

# Install a package
sudo dnf install nginx

# Upgrade packages
sudo dnf upgrade

# Remove a package
sudo dnf remove nginx
Package names, repositories, and commands can differ by distribution and version. Teach students to confirm the target distribution before copying installation commands from documentation.
TOPIC 16

Pipes, Redirection, and Command Composition

The shell becomes especially powerful when small tools are combined. Standard input, standard output, and standard error can be redirected or connected between commands.

>

Overwrite output

echo "hello" > file.txt

>>

Append output

date >> history.log

<

Input redirection

sort < names.txt

|

Pipe

Sends the output of one command to the input of another.

2>

Redirect errors

command 2> errors.log

&&

Conditional chaining

Run the next command only if the previous command succeeds.

Practical Examples

# Find matching processes
$ ps aux | grep nginx

# Count lines containing "ERROR"
$ grep "ERROR" app.log | wc -l

# Sort and count repeated values
$ sort users.txt | uniq -c

# Save disk usage output
$ df -h > disk-report.txt
A pipeline should be read from left to right: “produce data → filter it → transform it → summarize it.”
TOPIC 17

Introduction to Bash Scripting

Bash scripts automate repeated command-line tasks. A script is a text file containing shell commands, variables, conditions, loops, and functions.

First Script

#!/usr/bin/env bash

name="Cloud Student"

echo "Hello, $name"
echo "Current date: $(date)"
echo "Current directory: $(pwd)"

Make It Executable

$ chmod u+x hello.sh
$ ./hello.sh

Conditions

#!/usr/bin/env bash

if command -v docker >/dev/null 2>&1; then
  echo "Docker command is available."
else
  echo "Docker command was not found."
fi

Loops

#!/usr/bin/env bash

for service in nginx ssh cron
do
  echo "Checking: $service"
done
Professional scripts should validate inputs, quote variables where appropriate, check exit statuses, produce understandable errors, and avoid embedding secrets.
TOPIC 18

SSH and Remote Linux Administration

Secure Shell (SSH) is a standard method for remotely accessing Linux servers. In cloud environments, students may spend more time in SSH sessions than in a graphical desktop.

Basic Connection

$ ssh student@203.0.113.10

Using a Key File

$ ssh -i ~/.ssh/cloud-lab-key student@203.0.113.10

Secure Copy Example

$ scp report.txt student@203.0.113.10:/home/student/

Cloud providers often provision instances with key-based authentication. Private keys should be protected carefully and should never be published in a public repository.

Credential safety: Never place real private SSH keys, passwords, API tokens, or cloud credentials in lecture screenshots, source repositories, or shared scripts.

Cloud virtual machines behave like remote computers. A Linux cloud instance typically has virtual CPU, memory, storage, network interfaces, an operating-system image, and access-control settings.

Typical Cloud Administrator Workflow

Provision a Linux VM

Select an image, instance size, storage, networking, and security settings.

2

Connect securely

Use SSH and a protected authentication method.

3

Update the system

Refresh package metadata and install approved security/software updates according to policy.

TOPIC 20

Linux and Containers

Containers isolate application processes while sharing the host operating-system kernel. Linux kernel capabilities such as namespaces and control groups are foundational to common Linux container runtimes.

Virtual Machine vs. Container

Virtual MachineContainer
Includes a guest operating system/kernelShares the host kernel
Usually heavierUsually lighter
Strong VM-level isolation boundaryProcess-level isolation mechanisms
Boots an OS environmentStarts application processes

Why Linux Skills Still Matter

  • Container images contain Linux files, directories, packages, and permissions.
  • Logs and configuration are frequently handled with shell tools.
  • File ownership can affect bind mounts and application behavior.
  • Networking concepts apply to ports, interfaces, bridges, and service communication.
  • Shell scripts commonly automate builds, startup, deployment, and diagnostics.

Illustrative Container Commands

# Show running containers
$ docker ps

# Run a temporary shell in an Ubuntu image
$ docker run --rm -it ubuntu bash

# List files inside that container
root@container:/# ls /

# Exit the shell
root@container:/# exit

These commands are demonstrations only and require a container runtime such as Docker to be installed and configured on the laboratory machine.

TOPIC 21

Linux Security Practices

Secure administration is not a single command. It is a combination of access control, updates, logging, network restrictions, careful privilege use, and disciplined operational procedures.

01

Use least privilege

Operate as a normal user and elevate only when required.

02

Patch responsibly

Apply security and software updates according to organizational change policy.

03

Protect credentials

Keep SSH keys, passwords, and cloud tokens out of public files and repositories.

04

Restrict network access

Expose only required services and ports.

05

Review permissions

Avoid unnecessary write/execute access and overly permissive modes.

06

Inspect logs

Use logs to investigate authentication events, service failures, and configuration problems.

07

Back up important data

Backups should be tested, protected, and appropriate to recovery requirements.

08

Document changes

Professional administrators keep reproducible records of system changes.

TOPIC 22

A Professional Troubleshooting Method

Randomly trying commands can make incidents worse. A structured method improves speed, safety, and repeatability.

1

Define the symptom

What exactly is failing? When did it start? Which users or systems are affected?

2

Collect evidence

Check service state, process state, logs, disk capacity, memory, network paths, and recent changes.

3

Form a hypothesis

Use the evidence to identify the most likely causes instead of guessing.

4

Test safely

Prefer reversible, low-risk checks. Avoid destructive changes during diagnosis.

5

Apply and verify the fix

Correct the cause, then verify service functionality and check for side effects.

6

Document the incident

Record the cause, commands used, resolution, and prevention actions.

Useful Diagnostic Commands

$ df -h                 # filesystem capacity
$ free -h               # memory overview
$ uptime                 # load and uptime
$ ps aux                 # processes
$ systemctl --failed     # failed systemd units
$ journalctl -p err      # error-priority journal entries
$ ip addr                # interfaces and IPs
$ ip route               # routing
$ ss -tulpn              # listening sockets
TOPIC 23

Guided Laboratory: Linux Shell Fundamentals

This activity is designed for a disposable classroom VM, lab machine, or training environment. Do not use production servers for beginner exercises.

Hands-on Exercise

Build a Small Cloud-Lab Workspace

Students practice navigation, file creation, permissions, pipes, search, and a simple Bash script.

  1. Confirm the current user and system

    whoami
hostname
uname -a
pwd

    Explain: These commands establish identity, host, kernel/system information, and current location.

  2. Create a laboratory directory

    cd ~
mkdir -p cloud-linux-lab/{logs,scripts,reports}
cd cloud-linux-lab
ls -la

    Explain: Brace expansion lets Bash generate multiple directory names from one command.

  3. Create sample files

    printf "INFO service started\nERROR database unavailable\nINFO retrying\n" > logs/app.log
printf "server-01\nserver-02\nserver-01\n" > servers.txt

    Explain: > redirects output into a file and replaces previous content.

  4. Search and count

    grep "ERROR" logs/app.log
sort servers.txt | uniq -c

    Explain: The pipe connects one command's standard output to the next command's standard input.

  5. Create a report

    {
  echo "Linux Lab Report"
  echo "User: $(whoami)"
  echo "Host: $(hostname)"
  echo "Date: $(date)"
  echo "Path: $(pwd)"
} > reports/system-report.txt

cat reports/system-report.txt

  6. Create a Bash script

    cat > scripts/check.sh <<'EOF'
#!/usr/bin/env bash

echo "=== System Check ==="
echo "User: $(whoami)"
echo "Host: $(hostname)"
echo "Disk:"
df -h /
EOF

chmod u+x scripts/check.sh
./scripts/check.sh

    Explain: The script gathers a few non-destructive system details and demonstrates executable permissions.

  7. Inspect permissions

    ls -l scripts/check.sh
stat scripts/check.sh

    Explain: Ask students to identify owner, group, and permission bits.

  8. Clean up only the training workspace

    cd ~
rm -r cloud-linux-lab

    Explain before running: Confirm the exact directory with pwd and ls. This command removes the training directory recursively and should never be redirected to an unknown path.

Review Questions and Classroom Activities

Use these prompts after the lecture to test conceptual understanding, not just memorization of commands.

A

Concept Check

  1. What is the difference between the Linux kernel and a Linux distribution?
  2. What is the difference between a terminal and a shell?
  3. Why is / important in the Linux filesystem?
  4. What do r, w, and x represent?
  5. Why should administrators avoid working as root unnecessarily?
B

Command Interpretation

  1. Explain ls -la.
  2. Explain grep "ERROR" app.log | wc -l.
  3. Explain chmod 750 deploy.sh.
  4. Explain ip route.
  5. Explain journalctl -u ssh.
C

Cloud Scenario

A web application on a Linux VM is unreachable. Students should propose a safe troubleshooting sequence using service status, listening sockets, logs, IP addressing, routes, and HTTP testing.

D

A containerized application cannot write to a mounted directory. Ask students which Linux concepts might matter: ownership, permissions, process identity, path correctness, and mount configuration.

TOPIC 25

Key Terms and Glossary

Kernel
The operating-system core that manages hardware resources and provides low-level services.
Distribution
A complete operating system built around the Linux kernel with utilities, packages, and management tools.
Shell
A command interpreter such as Bash.
Terminal
An interface used to interact with a shell session.
Root directory
The top of the Linux filesystem hierarchy, represented by /.
Root user
The traditional superuser account with extensive administrative privileges.
sudo
A mechanism used to execute authorized commands with elevated privileges according to policy.
Package manager
A tool that installs, updates, removes, and tracks software packages.
Process
A running instance of a program.
Service
A long-running background capability such as SSH, a web server, or another system/application daemon.
Pipe
The | operator that passes one command's output into another command's input.
SSH
A protocol and toolset for secure remote access and related operations.
Container
An isolated application process environment that normally shares the host kernel.
Image
A packaged filesystem and metadata used as the starting point for a container.
