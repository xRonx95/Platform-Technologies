MODULE INTRODUCTION

Module Overview

Modern organizations require centralized systems for managing computers, applications, users, network resources, permissions, security policies, and authentication. Windows Server provides an enterprise server platform for implementing many of these infrastructure services.

Student-Friendly Explanation

Think of Windows Server as the central control system of an organization’s Windows network. Instead of configuring every computer separately, the administrator can place important services on servers and allow many client computers to use those services. Active Directory adds centralized identity management, which means the organization can manage users, computers, passwords, permissions, and policies from a common directory.

Simple Example

In a school with 300 computers, creating the same user account manually on every computer would be difficult. With Active Directory, the student can have one domain account and use that account on authorized computers throughout the school.

Centralized Management

The administrator can change a password policy, disable an account, create a security group, or apply a computer setting from a central management environment rather than visiting each workstation individually.

Why This Matters

Centralized administration improves consistency, reduces repetitive work, helps enforce security standards, and makes a large network easier to support and audit.

S

Windows Server

Windows Server is designed to operate server workloads such as file services, identity services, virtualization, application hosting, networking, storage, remote administration, and enterprise infrastructure.

AD

Active Directory

Active Directory Domain Services, commonly abbreviated as AD DS, provides centralized identity management, authentication, authorization, directory services, and administrative control within a Windows domain.

Professional Perspective

A Windows Server administrator does more than install an operating system. The administrator is responsible for availability, authentication, security, policy enforcement, network services, monitoring, backup, troubleshooting, and infrastructure continuity.

WINDOWS INFRASTRUCTURE

Windows Server Fundamentals

Windows Server is Microsoft's enterprise operating system platform for running infrastructure services and server workloads in physical, virtualized, cloud, and hybrid environments.

In Simple Terms

A normal desktop operating system is designed primarily for one person who uses applications, browses the web, and creates files. A server operating system is designed primarily to provide services to other computers. For example, one Windows Server may authenticate users, another may store shared files, and another may host business applications.

Client

A client requests a service. For example, a Windows 11 computer may request authentication, a shared folder, an IP address, or a website.

Server

A server responds to requests and provides a service. The server is normally configured to remain available for many users and devices at the same time.

Service

A service is a function provided over the network, such as DNS name resolution, authentication, file sharing, DHCP addressing, or web hosting.

Instructor Talking Point

Emphasize that “server” can refer to the physical machine, the virtual machine, or the service being delivered. In professional environments, a server is normally designed for reliability, security, controlled access, monitoring, backup, and continuous operation.

INFRASTRUCTURE SERVICES

Understanding Server Roles

A server role defines the primary function performed by a Windows Server computer. One server may operate multiple roles, although enterprise environments frequently separate critical workloads for security, performance, and availability.

Understanding Roles and Features

Windows Server starts as a general-purpose server operating system. Administrators add specific roles depending on what the machine must do. A role represents a major server responsibility, while a feature normally adds supporting functionality or management tools. The correct design is based on business requirements, not on installing every available role.

AD DS Example

When a user signs in using CORP\maria.santos, a domain controller can verify the identity and determine whether the account is allowed to access domain resources.

DNS Example

Instead of memorizing the IP address 192.168.10.10, users and computers can locate a server using a name such as dc01.corp.example.com.

DHCP Example

A newly connected client can automatically receive an IP address, subnet mask, default gateway, and DNS server information instead of requiring manual network configuration.

AD DS

Provides centralized authentication, directory services, identity management, and domain management.

DNS Server

Resolves host names and supports service discovery required by Active Directory.

DHCP Server

Automatically distributes IP addressing configuration to network clients.

File Services

Provides centralized storage, file sharing, quotas, permissions, and storage management.

Hyper-V

Provides Microsoft virtualization technology for hosting virtual machines.

Web Server IIS

Hosts websites, web applications, APIs, and related HTTP/HTTPS workloads.

Infrastructure Design Note

Installing every possible role on one production server increases operational complexity and can increase security risk. Enterprise systems should separate workloads when reliability, security, or scale requires it.

INFRASTRUCTURE ARCHITECTURE

Windows Server Deployment Models

How to Choose a Deployment Model

The operating system can perform similar server functions whether it runs on physical hardware, inside a virtual machine, or in a cloud environment. The main differences involve where the computing resources are located, who manages the hardware, how quickly resources can be scaled, and how the organization handles cost, redundancy, security, and connectivity.

Physical vs. Virtual

A physical server uses dedicated hardware. A virtual server shares physical hardware through a hypervisor. Virtualization is widely used because it allows multiple isolated server workloads to run on one physical host and makes laboratories easier to build.

On-Premises vs. Cloud

On-premises infrastructure is located within facilities controlled by the organization. Cloud infrastructure uses resources hosted by a cloud provider. A hybrid design combines both approaches when applications, identities, management, or workloads need to span them.

01

Physical Server

Windows Server runs directly on dedicated physical hardware located inside an organization's data center.

02

Virtual Machine

Windows Server operates as a virtual machine through a hypervisor such as Hyper-V.

03

Cloud Server

Windows Server operates as an infrastructure virtual machine hosted by a cloud provider.

04

Hybrid Infrastructure

On-premises Windows Servers integrate with cloud management, monitoring, security, and identity services.

DEPLOYMENT PROCEDURE

Installing Windows Server

Before Active Directory can be configured, administrators need a stable Windows Server installation with appropriate hardware resources and network connectivity.

What Students Should Understand Before Installation

Installing Windows Server is only the beginning. Before making the server a domain controller, the administrator should decide its purpose, assign sufficient CPU and memory, plan storage, configure networking, choose a meaningful computer name, apply updates, and confirm that the server can communicate correctly with the rest of the laboratory network.

Why CPU and Memory Matter

Server roles consume processor and memory resources. If a virtual machine has too few resources, installation and administration may become slow and services may respond poorly.

Why Storage Matters

The server needs storage for the operating system, logs, updates, applications, Active Directory data, and possibly shared files. Production storage also requires a backup plan.

Why Networking Matters

Active Directory is a network service. If clients cannot reach the domain controller or cannot resolve its DNS records, authentication and domain operations will fail.

SERVER PREPARATION

Initial Windows Server Configuration

A domain controller should have predictable networking and a meaningful computer name before Active Directory Domain Services is deployed.

Why Initial Configuration Comes Before AD DS

A domain controller becomes a permanent reference point for many network services. Changing basic identity or network settings after deployment can create unnecessary problems. For this reason, administrators normally establish the correct server name, static IP configuration, DNS settings, time configuration, updates, and network connectivity before promoting the machine to a domain controller.

Why Use a Meaningful Computer Name?

Names such as DC01, FILE01, and WEB01 immediately communicate the role of a server. Clear naming becomes especially important when an organization manages dozens or hundreds of servers.

Why Use a Static IP?

Clients need a stable location for DNS and directory services. If the domain controller’s address changes unexpectedly, devices may continue trying to contact the old address and domain services can become unavailable.

IDENTITY INFRASTRUCTURE

What Is Active Directory?

Active Directory Domain Services is a directory service that stores and organizes information about network objects while providing centralized mechanisms for authentication, authorization, administration, and policy management.

Active Directory as a Digital Organization Directory

A useful analogy is a secure organizational directory. It contains records representing people, computers, groups, and other resources. Unlike a simple contact list, however, Active Directory also participates in authentication and authorization. It helps answer two important questions: “Who are you?” and “What are you allowed to access?”

Authentication

Authentication verifies identity. When Maria enters her domain username and password, the domain environment checks whether those credentials represent a valid account.

Authorization

Authorization determines what an authenticated identity can do. Maria may be allowed to open the Accounting folder but denied access to the Human Resources folder.

Directory Service

The directory stores structured information so administrators and services can locate and manage objects such as users, groups, computers, and organizational units.

Core Definition

Active Directory Domain Services — AD DS

A hierarchical enterprise directory service used to manage identities and resources such as users, computers, groups, organizational units, servers, and security principals.

What Can Active Directory Manage?

User Accounts

Employee and administrator identities.

Computer Accounts

Domain-connected computers and servers.

Security Groups

Collections used to assign access permissions.

Policies

Centralized configuration and security settings.

Resources

Shared folders, printers, applications, and services.

Authentication

Verification of identities throughout a domain.

DIRECTORY ARCHITECTURE

Active Directory Logical Structure

Think of the Structure from Largest to Smallest

A forest is the broadest Active Directory structure shown in this lesson. Inside a forest are one or more domains. Inside a domain, administrators can create Organizational Units to arrange objects according to management needs. Individual user, computer, and group accounts are then stored within the directory structure.

Forest Example

A large organization may operate multiple domains that still belong to one forest and share the same overall Active Directory schema and configuration.

Domain Example

corp.example.com is the demonstration domain in this lesson. Users and computers can become members of that domain and use its authentication services.

OU Example

An OU called Faculty may contain faculty user accounts. A policy linked to that OU can then target those accounts without applying to every user in the domain.

ROLE INSTALLATION

Installing Active Directory Domain Services

Active Directory is installed as a Windows Server role. The role installation provides the binaries and management tools required before the computer can be promoted to a domain controller.

Two Separate Stages

Students should distinguish between installing the AD DS role and promoting the server to a domain controller. Installing the role places the necessary software and management components on Windows Server. Promotion performs the directory configuration that actually turns the server into a domain controller.

Stage 1 — Install the Role

Windows Server receives the AD DS binaries and administrative tools. At this point, the machine is prepared for Active Directory configuration but is not yet functioning as a domain controller.

Stage 2 — Promote the Server

The administrator chooses whether to create a new forest, create a new domain, or add another domain controller to an existing domain. Directory-specific settings are then configured and the server restarts.

DOMAIN DEPLOYMENT

Promoting the Server to a Domain Controller

Installing AD DS does not automatically make the machine a domain controller. A separate configuration process must promote the server and configure the Active Directory domain.

What a Domain Controller Actually Does

A domain controller is a Windows Server that runs Active Directory Domain Services and participates in the security of the domain. It stores directory information, processes authentication requests, helps enforce domain security policies, and allows computers and services to locate directory resources.

User Signs In

The client contacts domain services to verify the user’s credentials and obtain information required for domain access.

Computer Joins Domain

A computer account is created or used in Active Directory so the device becomes a trusted member of the domain.

Policy Is Applied

Domain and OU-linked policies can be delivered to domain users and computers according to the administrator’s configuration.

Production Design Note

Organizations commonly deploy more than one domain controller for resilience. If one controller becomes unavailable, another can continue providing directory services. Redundancy, replication, backup, monitoring, and recovery planning are therefore important AD DS design concerns.

NAME RESOLUTION

Active Directory and DNS

DNS is fundamental to Active Directory. Domain-joined computers use DNS records to locate domain controllers and directory services.

Why DNS Is More Than “Name to IP” in Active Directory

DNS is used not only to find a server by name but also to locate specific Active Directory services. AD DS registers service records so clients can discover domain controllers and other required services. If the client uses the wrong DNS server, it may have Internet access and still fail to find the domain.

Successful Example

PC01 uses 192.168.10.10 as its DNS server. When PC01 searches for the corp.example.com domain, the DNS service on DC01 can return the records that identify the domain’s services.

Failure Example

PC01 uses only an unrelated public DNS server. Public DNS may resolve Internet websites, but it does not contain the private Active Directory service records for the classroom domain, so the client may be unable to join or locate the domain.

CLIENT PC01
DNS Query →
DNS corp.example.com

Important DNS Concepts

A Record

Maps a host name to an IPv4 address.

dc01.corp.example.com → 192.168.10.10

SRV Record

Identifies servers providing specific network services. Active Directory relies heavily on SRV records.

Forward Lookup

Resolves a host or domain name to an IP address.

Reverse Lookup

Resolves an IP address back to a host name when an appropriate reverse zone exists.

Common Laboratory Error

A domain-joining problem is frequently caused by incorrect DNS configuration. A client intended to join the laboratory domain should use the Active Directory DNS service rather than an unrelated public DNS server for domain resolution.

DIRECTORY ORGANIZATION

Organizational Units

Organizational Units allow administrators to create a logical management structure inside a domain. OUs are commonly designed according to organizational, administrative, geographic, or technical requirements.

Why Organizational Units Are Important

OUs are not just folders used to make the directory look organized. They are administrative containers. Administrators can delegate responsibility over selected OUs and link Group Policy Objects to them. A well-designed OU structure therefore supports both management and policy targeting.

Department-Based OU

Create OUs such as Accounting, Human Resources, and IT when departments require different administration or policies.

Device-Based OU

Create OUs such as Laboratory PCs, Office PCs, and Servers when different device types require different computer policies.

Delegation Example

A help-desk technician can be delegated permission to reset passwords in one OU without receiving full administrative control over the entire domain.

IDENTITY MANAGEMENT

Managing Users and Security Groups

Centralized account administration is one of the most important benefits of Active Directory. Administrators can create, organize, disable, reset, secure, and audit domain accounts.

User Accounts vs. Security Groups

A user account represents an individual identity. A security group represents a collection of identities that should receive similar access. Instead of granting a file permission separately to Maria, John, and Alex, the administrator can place them in the Accounting group and grant the resource permission to that group.

User Account

Stores identity-related information such as the sign-in name, account status, group memberships, and other directory attributes.

Security Group

Simplifies authorization by allowing permissions to be assigned to a role or department instead of to each person individually.

Lifecycle Management

When an employee changes department, administrators can often modify group membership instead of manually editing permissions on every shared resource.

CLIENT INTEGRATION

Joining a Computer to the Domain

Joining a compatible Windows computer to Active Directory establishes a computer account and allows domain identities and centralized policies to be used on that device.

What Changes When a Computer Joins the Domain?

The computer becomes a recognized member of the Active Directory environment. A computer account represents the device in the directory, domain users can authenticate on the device when permitted, and centralized Group Policy settings can be applied. Domain membership creates a managed trust relationship between the client and the domain.

Before Domain Join

The workstation is normally managed using local accounts and local settings. An account created only on that PC generally exists only on that machine.

After Domain Join

Authorized domain identities can be used, the computer can receive domain policies, and administrators can manage the device as part of the organization’s directory structure.

Before Joining the Domain

  • Client and domain controller have network connectivity.
  • The client uses the correct Active Directory DNS server.
  • The domain name can be resolved.
  • The client clock is synchronized appropriately.
  • Authorized credentials are available.

CENTRALIZED CONFIGURATION

Group Policy

Group Policy provides centralized configuration management for domain users and computers. Administrators can define settings once and apply them across selected portions of the organization.

Think of Group Policy as Centralized Rules

Without Group Policy, an administrator might need to configure the same security or desktop setting manually on every workstation. A Group Policy Object allows the administrator to define many settings centrally and apply them to selected users or computers through sites, domains, and Organizational Units.

Security Example

An organization can configure account, firewall, auditing, or other security-related settings consistently across targeted computers.

User Experience Example

Administrators can control selected desktop settings or restrict access to particular configuration areas for specific users.

Management Benefit

Centralized policy reduces configuration differences between machines and makes changes easier to document, repeat, and troubleshoot.

Important Processing Concept

The Local, Site, Domain, and OU sequence is a useful starting model, but actual Group Policy results can also be affected by inheritance, enforced links, security filtering, WMI filtering, loopback processing, and other configuration choices. Students should use tools such as gpresult when troubleshooting what actually applied.

RESOURCE SECURITY

File Sharing and NTFS Permissions

Windows Server frequently provides centralized storage. Administrators need to understand both shared-folder permissions and NTFS permissions when controlling access to files.

Share Permissions and NTFS Permissions Work Together

When a folder is accessed across the network, the user may be affected by both the shared-folder permission and the NTFS permission on the files or folders. Effective access therefore depends on the combined configuration. Administrators should design permissions carefully and test access using accounts that represent real user roles.

Example: Accounting Folder

The Accounting security group might receive Modify access to a finance folder so members can create and update documents. Other employees may receive Read access or no access, depending on business requirements.

Why Avoid “Everyone Full Control”?

Excessive permissions increase the chance of accidental deletion, unauthorized changes, information exposure, and malware impact. Permission design should follow least privilege.

Permission Purpose
Read View files and folder contents.
Write Create or modify data where permitted.
Modify Read, write, change, and delete permitted files.
Full Control Provides broad control including permission management where applicable.
Least Privilege

Users should receive only the level of access necessary to perform their assigned responsibilities.

Windows PowerShell for Active Directory

PowerShell provides administrators with a scriptable and repeatable method of managing Windows Server and Active Directory.

Why Administrators Learn PowerShell

A graphical interface is convenient when performing one task. PowerShell becomes especially valuable when the same task must be repeated many times. For example, creating 200 users manually can be slow and inconsistent, while a carefully tested script can perform repetitive operations in a controlled and repeatable way.

Discovery

Automation

Scripts can standardize repetitive administrative tasks, reduce manual typing, and create a record of the procedure that was performed.

Safety

INFRASTRUCTURE PROTECTION

Windows Server & AD Security

Active Directory is a critical security component because it controls access to identities, computers, services, and enterprise resources.

Why Active Directory Security Is Critical

Active Directory can control access to many systems at once. A compromised privileged account may therefore create much greater risk than the compromise of a normal user account. Security design should reduce unnecessary privilege, protect administrative credentials, keep systems updated, monitor important events, and maintain recoverable backups.

Normal User Account

Used for routine work such as documents, approved applications, and ordinary access to organizational resources.

Administrative Account

Used only when privileged changes are required. Separating administrative activity reduces unnecessary exposure of elevated credentials.

Audit and Monitoring

Logs help administrators investigate failed sign-ins, account changes, policy events, and other activity that may indicate a configuration problem or security incident.

01

Least Privilege

Grant administrators and users only the rights required for their responsibilities.

02

Separate Admin Accounts

Use dedicated privileged accounts for administrative work instead of daily user accounts.

03

Strong Authentication

Implement appropriate password, lockout, and stronger authentication controls.

04

Patch Management

Maintain supported systems and deploy relevant security updates in a controlled manner.

05

Monitoring

Review logs, security events, administrative changes, and authentication activity.

06

Backups

Maintain tested backups and documented recovery procedures for critical infrastructure.

Critical Security Principle

Domain administrator credentials should not be used for ordinary web browsing, email, or routine workstation tasks. Privileged accounts require stronger operational protection.

BUSINESS CONTINUITY

Backup and Recovery

A successful infrastructure strategy considers failure before it occurs. Administrators require documented backup, restoration, and disaster-recovery procedures.

A Backup Is Useful Only If It Can Be Restored

Copying data is only one part of a recovery strategy. Administrators must know what is included in the backup, where the backup is stored, how it is protected, how long it is retained, and how the organization will restore service after failure. Recovery procedures should be tested before an emergency occurs.

Failure Scenario

A server may fail because of hardware problems, corruption, configuration mistakes, ransomware, accidental deletion, or environmental events.

Recovery Objective

The organization must decide which services are most important and how quickly they must be restored to support operations.

Testing

A restoration test verifies that backup data is usable and that administrators understand the documented recovery procedure.

Windows Server in Hybrid Cloud Infrastructure

Windows Server is no longer limited to traditional on-premises server rooms. Modern environments can combine local Windows Server infrastructure with cloud management and services.

What “Hybrid” Means

Hybrid infrastructure means the organization uses both local infrastructure and cloud-based capabilities. A Windows Server can remain physically located in the organization while selected management, monitoring, backup, security, identity, or application services integrate with cloud platforms.

Why Keep Some Services On-Premises?

Organizations may have local applications, data-location requirements, existing hardware, specialized network dependencies, or operational reasons for retaining some workloads on-site.

Why Use Cloud Services?

Cloud services can provide flexible capacity, centralized management, remote visibility, globally available services, and additional security or monitoring capabilities depending on the organization’s architecture.

APPLICATION ISOLATION

Introduction to Windows Containers

Containers provide an application deployment model that packages applications with their dependencies while providing isolation from other application workloads.

Containers Are Not Small Virtual Machines

Both virtual machines and containers provide isolation, but they do so differently. A virtual machine normally includes its own guest operating system. A container packages an application and its dependencies while using the container capabilities of the host environment. This can make containers faster to create and easier to reproduce for suitable application workloads.

Image

A container image is a packaged template containing the application and required components used to create container instances.

Container

A container is a running or created instance based on an image. Multiple containers can be created from the same image.

Use Case

SYSTEMATIC DIAGNOSIS

Windows Server & AD Troubleshooting

Professional troubleshooting should be evidence-based and systematic. Avoid making multiple unrelated configuration changes before identifying the actual failure domain.

A Professional Troubleshooting Method

Start by identifying exactly what is failing, determine the scope, gather evidence, test the simplest likely causes, make one controlled change at a time, verify the result, and document the final resolution. Randomly changing many settings can hide the original cause and create additional problems.

1. Define the Symptom

“The domain is broken” is too broad. A better description is “PC01 cannot resolve corp.example.com using the configured DNS server.”

2. Test by Layer

Check physical or virtual connectivity, IP configuration, DNS resolution, service availability, credentials, permissions, and policy processing in a logical order.

3. Confirm the Fix

After correcting the cause, repeat the original test and verify that related services still operate correctly. Record what was changed for future support.

Problem Client cannot join domain
Check

DNS configuration, connectivity, domain name, credentials, and time.

Problem User cannot sign in
Check

Account status, password, network connectivity, DNS, domain-controller availability, and time.

Problem GPO does not apply
Check

OU placement, GPO links, permissions, filtering, inheritance, DNS, and policy results.

Problem Name cannot be resolved
Check

DNS server address, DNS zones, records, network connectivity, and service status.

How Students Should Approach the Laboratory

Before Each Change

After Each Change

Document the Laboratory

Record server names, IP addresses, domain names, OU structure, user accounts, policies, commands, screenshots, problems encountered, and how each problem was resolved.

STUDENT UNDERSTANDING

Key Concepts Explained in One Scenario

The following scenario connects the major topics in the module so students can see how Windows Server, Active Directory, DNS, users, groups, Group Policy, and permissions work together as one system rather than as unrelated topics.

Scenario: A New Accounting Employee Joins the Organization

Maria Santos is hired by the Accounting department. The administrator must give Maria a secure identity, allow her to use a company computer, provide access to the Accounting shared folder, and apply the organization’s standard workstation policies.

1

Create Maria’s Domain User Account

The administrator creates maria.santos in the appropriate Active Directory OU. This creates Maria’s centralized organizational identity.

2

Add Maria to the Accounting Security Group

Instead of granting folder access directly to Maria, the administrator adds her to the Accounting group. Permissions can now be managed according to job role.

3

Prepare the Accounting Workstation

The workstation is configured with correct network and DNS settings and is joined to corp.example.com. Active Directory now recognizes the computer as a domain member.

4

Maria Signs In

The client uses domain services to authenticate Maria. Successful authentication proves who she is; authorization then determines what resources she may use.

5

Group Policy Applies

Policies linked to the relevant domain or OU can configure approved workstation and security settings. The administrator can verify the resulting policy using gpresult /r.

6

Maria Opens the Accounting Share

Access is granted because Maria is a member of the Accounting security group and that group has the required permission. The administrator manages access through group membership rather than editing every user individually.

The Big Picture

DNS helps the workstation locate domain services. Active Directory stores the user and computer identities. The domain controller authenticates the user. Security groups simplify authorization. Group Policy applies centralized settings. File permissions protect the resource. These technologies work together to create a manageable enterprise environment.
