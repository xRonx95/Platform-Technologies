Cloud & Containers · Module 1 · Lesson 03

Windows Installation and Disk Partitioning

Every container host, hypervisor and cloud workstation begins with a correctly installed operating system on a correctly planned disk. This lecture examines the firmware, the partition table, the file system and the installation procedure that together produce a stable Windows host—one that is ready to run Hyper-V, WSL 2 and Docker.

Duration: 3 hours Theory + Hands-on Laboratory Prerequisite: Lesson 02 — Computer Hardware
SECTION 00

Lesson Overview

Installation is not a single click. It is a sequence of decisions—firmware mode, partition scheme, partition sizes, file system—each of which constrains what the machine can do for the remainder of its service life.

A student who installs Windows without understanding these decisions may still arrive at a working desktop, but the result is fragile. A disk initialised in the wrong scheme cannot boot in the wrong firmware mode. A system partition sized without foresight will refuse a feature update two years later. A host without virtualization enabled in firmware cannot run a single container. This lesson therefore treats installation as an engineering task with defined inputs, defined outputs and verifiable results.

SECTION 01

Learning Outcomes

Upon completion of this lesson, the student will be able to:

  • Differentiate legacy BIOS from UEFI firmware and explain the boot sequence of each.
  • Compare the MBR and GPT partitioning schemes and justify the selection of GPT for modern installations.
  • Identify the four standard partitions created by Windows Setup on a UEFI system and state the purpose of each.
  • Prepare bootable installation media and configure firmware boot order and Secure Boot correctly.
  • Perform a clean installation of Windows using both the guided interface and the DiskPart command-line method.
  • Design a partition layout appropriate to a workstation that will host virtual machines and containers.
  • Verify that the completed installation uses UEFI, GPT and hardware virtualization.
  • Diagnose and resolve the common installation failures listed in the troubleshooting guide.
SECTION 02

Why This Matters in a Cloud and Containers Course

It is reasonable for a student to ask why a course concerned with cloud platforms and containers devotes a full session to installing a desktop operating system. The answer is that the abstractions studied later in the course rest directly on the decisions made here.

Containers share the host kernel

A container is not a virtual machine. It is an isolated process served by the host kernel. The health, configuration and storage layout of that host determine the behaviour of every container running on it.

WSL 2 and Hyper-V require firmware support

Docker Desktop on Windows relies on a lightweight virtual machine. Without Intel VT-x or AMD-V enabled in firmware, the engine will not start—a failure that originates before the operating system loads.

Images consume real disk

Container images, build caches and volumes accumulate quickly. A laboratory machine partitioned with a small system volume will exhaust its free space within weeks of regular use.

Cloud provisioning mirrors this process

Choosing an image, sizing a disk, selecting a boot mode and attaching storage is exactly what an engineer does when provisioning a virtual machine on any cloud platform. The vocabulary is identical.

Concept anchor

Treat the physical machine in front of you as your first server. Every choice you make during installation is the same class of choice you will later make through a cloud console or an infrastructure-as-code template.

SECTION 03

Firmware: Legacy BIOS versus UEFI

Firmware is the software stored on the motherboard that runs before any operating system exists. Its responsibilities are to test the hardware, initialise devices and locate a boot loader. Two generations of firmware are in service today, and the difference between them governs how the disk must be partitioned.

Legacy BIOS

The Basic Input/Output System dates from the earliest personal computers. After power-on self-test, it reads the first 512-byte sector of the selected disk—the Master Boot Record—and executes the small program stored there. BIOS operates in 16-bit real mode, addresses disks through the MBR scheme, and therefore cannot boot from a volume larger than approximately 2 TB.

UEFI

The Unified Extensible Firmware Interface replaces that model. UEFI understands file systems directly: it reads a FAT32 partition called the EFI System Partition and executes a boot loader file stored inside it, typically \EFI\Microsoft\Boot\bootmgfw.efi. Because UEFI pairs with the GPT scheme, it supports very large disks, faster start-up, and the cryptographic verification known as Secure Boot.

Table 3.1 — Comparison of firmware interfaces
CharacteristicLegacy BIOSUEFI
Required partition schemeMBRGPT
Maximum bootable diskApproximately 2 TB9.4 ZB (theoretical)
Partition limit4 primary, or 3 + extended128 in the Windows implementation
Boot loader locationSector 0 of the diskFile inside the EFI System Partition
Secure BootNot availableSupported
InterfaceText, keyboard onlyGraphical, mouse supported
Windows 11 supportNot supportedRequired
Critical rule

The firmware mode used to boot the installation media determines the partition scheme Windows will create. If the USB drive is started in legacy mode, Setup builds an MBR disk; if started in UEFI mode, Setup builds a GPT disk. This single detail is the origin of the most common installation error you will encounter in the laboratory.

SECTION 04

Storage Devices and Interfaces

Before partitioning a disk, the technician must know what kind of disk it is. Three device classes are commonly encountered, and they differ by an order of magnitude in performance.

Terminology the student must use precisely

  • Physical disk — the hardware device itself, listed by Windows as Disk 0, Disk 1 and so on.
  • Partition — a defined region of a physical disk, described by an entry in the partition table.
  • Volume — a formatted partition that carries a file system and, usually, a drive letter.
  • Drive letter — a label such as C: assigned by Windows; it is not a property of the hardware.
Teaching point

Students frequently say “the C drive” when they mean the physical disk. Insist on the correct term during the laboratory: a single physical disk can carry several volumes, and a single volume can, in advanced configurations, span several physical disks.

SECTION 05

Partition Schemes: MBR and GPT

A partition scheme is the on-disk data structure that records where each partition begins and ends. Windows supports two. The choice is made when the disk is initialised and cannot be changed later without either converting the disk or erasing it.

Table 5.1 — Selecting a partition scheme
SituationSchemeReasoning
New workstation for this courseGPTRequired by Windows 11 and by UEFI; supports Secure Boot.
Boot disk larger than 2 TBGPTMBR cannot address the space beyond the 2 TB boundary.
Very old machine with BIOS-only firmwareMBRThe firmware cannot read an EFI System Partition.
Removable media for wide compatibilityMBRAccepted by both firmware generations and by older devices.
SECTION 06

Anatomy of a Windows Disk

When Windows Setup is allowed to partition an empty GPT disk automatically, it creates four partitions. Only one of them is visible in File Explorer. Students must be able to name all four and explain why the hidden ones exist.

Do not delete

Deleting the EFI System Partition renders the machine unbootable. Deleting the Recovery partition removes the repair environment. Both are hidden by design; a technician who deletes them to “reclaim space” will recover approximately 850 MB and lose the ability to start or repair the computer.

SECTION 07

File Systems and Formatting

A partition is only a boundary. Formatting writes a file system into that boundary—the index structures that allow files to be created, located and secured.

Table 7.1 — File systems encountered during installation
File systemTypical useKey characteristics
NTFS The Windows system volume and all internal data volumes Journaling, permissions (ACLs), encryption, compression, file size limited only by volume size
FAT32 EFI System Partition; older USB media Universally readable; maximum single file size of 4 GB; no permissions
exFAT External drives shared between Windows, macOS and Linux No 4 GB limit; no journaling; not suitable for a system volume
ReFS Server data volumes and resilient storage Integrity checksums and automatic repair; cannot host the Windows boot volume

Quick format compared with full format

A quick format writes a new, empty file-system index and marks the whole area as free; the old data physically remains until it is overwritten. A full format additionally verifies every sector, which takes considerably longer but detects failing media. For a routine installation on a healthy disk, quick format is appropriate. For a disk that has produced read errors, or one being retired from service, use a full format.

Security note

Formatting is not secure erasure. If a disk holding confidential material is leaving the institution, it must be sanitised with a dedicated tool—or, for a solid-state device, with the manufacturer’s secure-erase utility.

SECTION 08

Partition Planning

Partition sizes should be decided before Setup is started, not improvised at the drive selection screen. The table below gives defensible starting figures for a machine used in this course.

Table 8.1 — Recommended layout for a 512 GB container-laboratory workstation
PartitionSizeJustification
EFI System100–300 MBCreated automatically; 300 MB gives room for additional boot loaders in a dual-boot design.
Microsoft Reserved16 MBFixed by Windows; not user-configurable.
Windows (C:)200–250 GBWindows requires ~64 GB; feature updates need ~20 GB free; Docker images and WSL distributions default to this volume.
Data / Projects (D:)200–250 GBSeparates source code, virtual machine files and datasets from the system, simplifying reinstallation.
Recovery~750 MBCreated automatically at the end of the disk.

Arguments for and against a separate data volume

In favour

Reinstalling Windows requires formatting only C:. Backups can target one volume. Filling the data volume with datasets cannot stop the operating system from functioning.

Against

Space cannot flow between volumes without resizing. On a small disk of 256 GB or less, splitting frequently produces two volumes that are each too small to be useful.

SECTION 09

Pre-Installation Checklist

Installation is destructive. The following checks are completed and confirmed before the installation media is inserted.

  1. Back up all user data

    Copy documents, browser profiles, licence keys and application settings to external media or cloud storage. Verify that the copy opens correctly before proceeding.

  2. Record the network and account details

    Wireless password, Microsoft account credentials, and any proxy configuration required by the institution.

  3. Confirm the hardware meets requirements

    Windows 11 requires a 64-bit processor of 1 GHz or faster with two or more cores, 4 GB of RAM, 64 GB of storage, UEFI with Secure Boot capability, and TPM 2.0. For this course, treat 16 GB of RAM and an NVMe SSD as the practical minimum.

  4. Obtain drivers in advance

    Download the network and storage drivers for the specific model from the manufacturer’s support page and keep them on the USB drive. A machine that installs successfully but has no network adapter driver cannot download its own drivers.

  5. Note the licence position

    A digital licence tied to the hardware reactivates automatically after a clean install of the same edition. A product key on a label must be recorded before the machine is wiped.

  6. Ensure stable power

    Connect the mains adapter. An interruption during the file-copy phase can leave the disk in an inconsistent state.

SECTION 10

Creating Bootable Installation Media

The installation media is a USB flash drive of at least 8 GB, prepared so that firmware can boot from it. Preparation erases the drive completely.

Source integrity

Installation images are obtained only from the official Microsoft download page or from a licensed volume-licensing portal. Images redistributed through file-sharing sites routinely contain modified system files and must never be used on institutional hardware.

SECTION 11

Firmware Setup and Boot Order

The firmware setup utility is entered by pressing a manufacturer-specific key immediately after power-on. Common keys are F2, Del, F10 and Esc. A one-time boot menu is usually available on F12 or F9.

Demonstration sequence

Enter setup, disable CSM, confirm Secure Boot is enabled, enable virtualization, place the USB device first in the boot order, then save and exit with F10. Perform these five actions in this order so that students can reproduce them from memory.

SECTION 12

Guided Installation Walk-through

From this point the machine is committed. Each screen below is reproduced so that students can recognise it and know what is expected of them before the demonstration begins.

  1. Boot from the installation media

    With the USB drive first in the boot order, restart the machine. If the message Press any key to boot from USB appears, press a key promptly; the prompt expires in a few seconds and the machine will fall through to the internal disk.

  2. Select language, time format and keyboard

    Choose the language and regional format required by the institution, then select the keyboard layout that matches the physical hardware. An incorrect layout will make the product key and password appear to be mistyped later.

  3. Select Install now and handle the product key prompt

    If the machine holds a digital licence, choose I don’t have a product key; Windows will activate automatically once it reaches the network. Otherwise enter the key recorded during preparation.

  4. Select the edition and accept the licence terms

    The edition chosen must match the licence. Windows 11 Pro is required for this course because Hyper-V, the sandbox and BitLocker are unavailable in the Home edition.

    Edition matters

    Docker Desktop can run on Home using the WSL 2 back end, but the Hyper-V exercises in Module 2 cannot. Install the Pro edition on all laboratory machines.

  5. Choose Custom: Install Windows only (advanced)

    The Upgrade path preserves files and applications and is used only when repairing an existing installation. Every clean installation uses the Custom path, which is the only route to the partitioning interface.

  6. Partition the disk

    This is the substance of the lesson and is treated separately in Section 13 below.

  7. Allow the file copy to complete

    Setup expands the image, installs features and updates, then restarts several times. Remove the USB drive at the first restart to prevent Setup from starting again from the beginning.

  8. Complete the out-of-box experience

    Set the region and keyboard, connect to the network, name the device according to the laboratory convention, sign in or create a local account, and review the privacy settings. Decline optional telemetry and advertising personalisation on institutional machines.

SECTION 13

Custom Partitioning Inside Windows Setup

The drive-selection screen is the only part of Setup that permanently destroys data. Work slowly here and read the disk numbers aloud before acting.

Procedure for a clean installation on one disk

  1. Identify the correct disk

    Match the reported capacity to the intended target. If a second disk is present, confirm its number before touching any control. Deleting a partition on the wrong disk destroys data that Setup cannot recover.

  2. Delete the existing partitions on the target disk

    Select each partition on Drive 0 in turn and choose Delete until the entire disk reports as a single block of unallocated space. This removes any previous EFI, recovery and OEM partitions that would otherwise be reused.

  3. Create the system partition

    With the unallocated space selected, choose New, enter the planned size in megabytes, and choose Apply. Setup will announce that it must create additional partitions for system files; accept this. The EFI, MSR and recovery partitions appear automatically.

  4. Create the data partition

    Select the remaining unallocated space, choose New again and apply the full remaining size. Do not assign a drive letter here; Windows will do so after installation.

  5. Select the primary Windows partition and continue

    Highlight the large primary partition created in step 3—not the EFI or recovery partition—and choose Next.

Point of no return

Choosing Next on this screen begins writing to the disk. Any partition deleted before this moment is gone; consumer recovery software rarely restores a partition that Setup has already formatted.

SECTION 14

Advanced Method: Partitioning with DiskPart

Pressing Shift + F10 at any point during Setup opens a command prompt. The diskpart utility available there gives exact control over the layout and is the method used when the graphical screen refuses to cooperate—for example when a disk must be converted from MBR to GPT.

Complete UEFI/GPT layout script

diskpart
list disk
select disk 0
clean                          :: removes ALL partitions on disk 0
convert gpt

create partition efi size=300  :: EFI System Partition
format quick fs=fat32 label="System"
assign letter=S

create partition msr size=16   :: Microsoft Reserved

create partition primary size=245760   :: 240 GB for Windows
format quick fs=ntfs label="Windows"
assign letter=W

create partition primary       :: remaining space for data
format quick fs=ntfs label="Data"
assign letter=D

list volume
exit
Verify before you clean

Always run list disk and confirm the disk number by its reported size before issuing select. clean applied to the wrong disk erases a customer’s data in under one second and produces no warning.

SECTION 15

Post-Installation Configuration

An installation is not finished when the desktop appears. The following sequence brings the machine to a supportable state.

  1. Verify firmware mode and partition scheme

    Run msinfo32. The BIOS Mode line must read UEFI and Secure Boot State must read On. Confirm the scheme in Disk Management by opening the disk properties and reading the Volumes tab.

  2. Install chipset and device drivers

    Install in this order: chipset, storage, graphics, network, audio, then peripherals. Windows Update supplies generic drivers, but the manufacturer’s packages provide power management and firmware updates that Windows Update does not.

  3. Apply all pending updates

    Run Windows Update repeatedly until no further updates are offered, restarting between passes. Cumulative updates frequently reveal further updates once installed.

  4. Confirm activation

    Open Settings → System → Activation. The status should read Windows is activated with a digital licence linked to your Microsoft account.

  5. Format and label the data volume

    Open Disk Management, assign a letter to the second partition, format it NTFS and give it a meaningful label such as Projects.

  6. Create a restore point and record the build

    Enable system protection on C: and create a named restore point. Record the machine name, edition, build number and disk layout in the laboratory inventory.

SECTION 17

Preparing the Host for Virtualization

This section is the bridge between the installation you have just completed and the container work that follows in Module 2.

Docker Desktop on Windows does not run containers directly on the Windows kernel by default. It runs a lightweight Linux virtual machine through WSL 2, which itself depends on the Windows hypervisor platform. The layers below must all be present.

Enabling the required Windows features

Verification commands

:: Confirm virtualization is active
systeminfo | findstr /i "Hyper-V Virtualization"

:: Install WSL 2 and a default distribution
wsl --install

:: Confirm the version in use
wsl --list --verbose
  NAME      STATE     VERSION
* Ubuntu    Running   2

:: Confirm the container engine responds
docker version
docker run --rm hello-world
Diagnostic shortcut

Open Task Manager, select the Performance tab and choose CPU. The line Virtualization: Enabled confirms layer 1 in two seconds without a reboot.

SECTION 18

Partitioning Decisions That Affect Containers

Container tooling is unusually demanding of the system volume, and the reasons are worth stating explicitly.

Table 18.1 — Where container tooling consumes disk space
ConsumerDefault locationTypical size
WSL 2 distribution virtual disk%LOCALAPPDATA%\Packages\...\ext4.vhdx2–60 GB, grows over time
Docker image layers and containers%LOCALAPPDATA%\Docker\wsl\10–80 GB in active use
Build cacheInside the Docker data volumeSeveral GB; grows with every build
Hyper-V virtual machinesC:\ProgramData\Microsoft\Windows\Hyper-V20–120 GB per virtual machine

Three practical rules

  1. Never size the system volume at the bare minimum. A 64 GB C: will run Windows and nothing else. Allocate 200 GB or more where the disk allows it.
  2. Relocate large virtual disks deliberately, not by accident. Hyper-V virtual machine files can be stored on the data volume by changing the default path in Hyper-V Manager. WSL distributions can be exported and re-imported to another location.
  3. Reclaim space on a schedule. docker system prune -a removes unused images, containers and cache. Teach this alongside partition planning, because together they determine whether the laboratory machine survives the semester.
Field observation

The most frequent cause of a broken container laboratory is not a broken container. It is a system volume with less than one gigabyte free, which prevents Windows from writing its page file, prevents Docker from extracting a layer, and produces error messages that name neither cause.

SECTION 19

Designing a Dual-Boot Laboratory Machine

Some exercises later in this course are more convenient on a native Linux installation. Where a machine must carry both operating systems, the partition layout is planned in advance and Windows is always installed first, because the Linux boot loader can detect and add Windows to its menu, while the reverse is not true.

Before you begin

Dual-boot installation is performed only on machines designated for it. Shrinking a production Windows volume to make room for Linux carries a real risk of data loss and must be preceded by a verified backup.

SECTION 20

Troubleshooting Guide

The following failures account for the large majority of unsuccessful installations in a teaching laboratory.

Table 20.1 — Installation errors, causes and resolutions
SymptomCauseResolution
“Windows cannot be installed to this disk. The selected disk has an MBR partition table.” Media booted in UEFI mode against an MBR disk Back up data, then use diskpart → clean → convert gpt, or convert non-destructively with mbr2gpt from a running system
“...the disk has a GPT partition table.” Media booted in legacy/CSM mode against a GPT disk Restart, enter firmware, disable CSM and select the UEFI entry for the USB device
The machine will not boot from the USB drive Boot order, Secure Boot rejecting the media, or the drive written with the wrong scheme Place the UEFI USB entry first; re-create the media with scheme GPT and target UEFI
“This PC can't run Windows 11” TPM 2.0 or Secure Boot disabled, or an unsupported processor Enable TPM (often labelled PTT or fTPM) and Secure Boot in firmware; verify the processor against the published support list
No disks are listed at the drive-selection screen Storage controller driver missing, or SATA mode set to RAID Use Load driver to supply the manufacturer’s storage driver, or set SATA mode to AHCI in firmware
Setup restarts into the installer repeatedly The USB drive remains first in the boot order Remove the media at the first restart, or return the internal disk to first place
Installation completes but there is no network Network driver not included in the image Install the driver prepared in Section 09 from the USB drive
Docker Desktop fails to start after installation Virtualization disabled in firmware, or the required Windows features are off Enable VT-x / AMD-V; enable Virtual Machine Platform and WSL; restart and run wsl --update

SECTION 23

Assessment Questions

Answer in full sentences. Each answer should demonstrate reasoning, not recall alone.

  1. Explain why a disk initialised as MBR cannot be booted by a UEFI system operating with CSM disabled.
    Model answer UEFI locates its boot loader as a file inside a FAT32 EFI System Partition, which exists only in the GPT layout. An MBR disk presents boot code in sector 0, which UEFI does not execute when compatibility support is disabled, so no boot loader is found.
  2. State the purpose of each of the four partitions created automatically by Windows Setup on a GPT disk.
    Model answer EFI System holds the boot loader; MSR reserves working space for disk management operations; the primary partition holds Windows and user data; the recovery partition holds the Windows Recovery Environment used for repair and reset.
  3. A technician deletes the 100 MB hidden partition to reclaim space. Describe the consequence and the remedy.
    Model answer The machine will not boot, because the EFI System Partition containing the boot loader has been removed. The remedy is to boot the installation media, open a command prompt, recreate the partition and rebuild the boot files with bcdboot C:\Windows /s S: /f UEFI.
  4. Why is 64 GB an unsuitable system-volume size for a machine used in this course?
    Model answer Windows itself consumes most of that space, and feature updates require roughly 20 GB of free space. WSL virtual disks, Docker image layers and build caches are all written to the system volume by default and routinely exceed 30 GB in normal course work.
  5. A student reports that Docker Desktop will not start on a freshly installed machine. Give an ordered diagnostic procedure.
    Model answer Confirm virtualization is enabled (Task Manager, Performance, CPU); if disabled, enable VT-x or AMD-V in firmware. Then confirm Virtual Machine Platform and WSL are enabled in Windows Features. Then run wsl --list --verbose to confirm version 2, and wsl --update if the kernel is outdated. Finally check free space on the system volume.
  6. Compare quick format and full format, and state which is appropriate for a disk that has been returning read errors.
    Model answer Quick format writes a new file-system index only; full format additionally verifies every sector. A disk returning read errors should receive a full format, because sector verification identifies bad areas and marks them unusable.
  7. Explain why Windows is installed before Linux on a dual-boot machine.
    Model answer The Linux boot loader detects an existing Windows installation and adds it to the boot menu. The Windows boot manager does not detect Linux, so installing Windows second overwrites the shared boot entries and hides the Linux installation until the loader is repaired.
  8. Relate one decision made during installation to a decision an engineer makes when provisioning a cloud virtual machine.
    Model answer Answers will vary. A strong answer maps disk sizing to selecting a managed-disk size, firmware mode to selecting a generation or boot-mode setting, and the image edition to selecting a machine image from a catalogue.
SECTION 24

Glossary

BIOS
Basic Input/Output System. Legacy motherboard firmware that boots from the Master Boot Record.
UEFI
Unified Extensible Firmware Interface. Modern firmware that boots a loader file from the EFI System Partition and supports Secure Boot.
Secure Boot
A UEFI facility that permits only cryptographically signed boot loaders to execute.
MBR
Master Boot Record. Legacy partition scheme limited to four primary partitions and approximately 2 TB.
GPT
GUID Partition Table. Modern partition scheme supporting up to 128 partitions in Windows, with a checksummed backup table at the end of the disk.
EFI System Partition (ESP)
A small FAT32 partition holding boot loaders. Required for UEFI booting.
MSR
Microsoft Reserved Partition. Reserved working space with no file system, used by disk management operations.
Windows Recovery Environment
A minimal Windows image stored in the recovery partition, used for startup repair, system reset and command-line recovery.
NTFS
New Technology File System. The journaled file system used for Windows system and data volumes.
Partition
A defined region of a physical disk described by an entry in the partition table.
Volume
A formatted partition carrying a file system, usually presented with a drive letter.
DiskPart
The Windows command-line disk partitioning utility, available during Setup through Shift + F10.
TPM 2.0
Trusted Platform Module. A hardware security processor required by Windows 11 and used by BitLocker.
Hypervisor
Software that creates and runs virtual machines by partitioning physical hardware resources.
WSL 2
Windows Subsystem for Linux, version 2. Runs a real Linux kernel in a lightweight virtual machine and provides the default back end for Docker Desktop.
Container
